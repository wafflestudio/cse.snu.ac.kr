# 타이포 위계와 본문 읽기 밀도 — DS-015 확정·적용

[현재 DS](index.html) · [실제 글 비교](type-density.html) · [진행 현황](PLAN.md)

**T-Q2는 B로 결정했다(DS-015). 공지 상세의 공개 읽기 본문에 16px/32px를 적용하고 승인 견본과 일치를 확인했다.** 아래는 승인 당시의 비교 이유·관찰·범위다. 다른 역할의 크기까지 확정한 것은 아니다.

## 현재 문제 → 제안 이유 → 기대 효과

현재 읽는 본문은 기본 14px·400·줄높이 28px이다. 버튼·폼 라벨도 14px이지만 용도가 다르다.
같은 크기를 쓰는 것 자체가 잘못은 아니다. 지금 필요한 것은 긴 글을 읽는 밀도와 짧은 조작 문구의 크기를 각각 선택할 기준이다.

**B: 읽는 본문 기본 16px, 기존 줄높이 비율 2 유지(32px)를 추천한다.**
긴 문장을 읽는 글자를 조금 키우고, 제목·메뉴·입력 등 조작 UI의 기존 밀도는 유지하는 안이다.
실제 읽기 속도가 개선됐다는 사용자 실험 결과가 아니라, 더 큰 글자를 우선하는 디자인 제안이다.
접근성 위반 판정이나 필수 크기로 제시하는 값은 아니다.

대신 줄바꿈과 스크롤이 늘어난다. 이번 표본은 본문 높이가 데스크톱 약 25%, 모바일 약 21% 증가했다.
기존의 작고 조밀한 인상이 더 중요하면 **A: 14px/28px 유지**가 맞다. 둘 다 선택 가능한 밀도다.

## A와 B의 차이

| 항목 | A — 현재 유지 | B — 추천 |
| --- | --- | --- |
| 기본 본문 | 14px / 400 | 16px / 400 |
| 기본 줄높이 | 28px (2배) | 32px (2배) |
| 기본 문단 아래 간격 | 10px | 10px 유지 |
| 정렬 | 기존 양끝 정렬 | 유지. 정렬의 별도 개선은 이번에 섞지 않음 |
| 기본 h2 | 21px / 줄높이 42px | 24px / 줄높이 48px |
| 기본 h3 | 약 16.38px / 줄높이 약 32.76px | 약 18.72px / 줄높이 약 37.44px |
| 본문 제목 주변 em 여백 | 본문 크기를 따름 | 크기와 함께 증가 |
| 작성자가 지정한 18px 표본 | 18px / 36px | 18px / 36px 유지 |
| 페이지·공지 고유 제목 / 메뉴·폼 | 현재 값 | 현재 값 |

본문의 기본 크기를 상속하는 문단·목록·강조는 B에서 함께 커진다.
본문 안 상대 단위 제목·여백도 영향을 받으며, “문단 글자만 커지고 나머지는 완전히 동일”한 안은 아니다.
px로 따로 지정된 내용과 상대 크기는 구분한다. 모든 작성자 HTML의 표현을 일괄 보증하지 않는다.

## 실제 표본에서 측정한 변화

로컬 공지에 한국어·영어 긴 문단, h2·h3, 목록과 명시적 18px 표본을 넣었다.
같은 DOM에서 읽기 컨테이너의 기본 크기만 바꿨다. 내용·폭·기본 줄높이 비율은 그대로다.

| 화면 | 본문 폭 | A 높이 → B 높이 | 첫 한국어 문단 줄 수 | 첫 영어 문단 줄 수 |
| --- | --- | --- | --- | --- |
| 1280px | 720px 동일 | 736.5 → 924.1px (+25.5%) | 2 → 3 | 4 → 4 |
| 390px | 350px 동일 | 1142.5 → 1388.1px (+21.5%) | 4 → 5 | 7 → 7 |

[측정 원자료](type-density-comparison/measurements.json). 제목·목록·강조도 포함한 본문 높이이며 모든 글의 증가율은 아니다.
새 프로덕션 프론트·기존 로컬 API, Playwright 1.57.0 Linux Chromium에서 확인했다.
조사 전용 공지는 확인 후 삭제했다. 운영 콘텐츠나 기존 시드 글을 수정하지 않았다.

## 첫 적용 범위와 이후 순서

선택할 것은 **긴 글 본문의 기본 밀도**다. B를 선택하면 첫 구현은 공지 상세의 공개 읽기 본문에 한정한다.
기존 HTMLViewer를 사용하는 해당 영역에 크기를 지정해 에디터와 공유 CSS의 크기를 바꾸지 않는다.
제목·관리 입력·메뉴·버튼 크기는 유지한다. 공지의 본문 내 상대 크기 제목·목록·강조는 위 표대로 함께 영향을 받는다.
다른 소개·프로필·연구·학사 본문은 표·이미지와 함께 배치를 대조한 뒤 도입하며 자동으로 확대하지 않는다.
A를 선택하면 이 범위의 기존 14px/28px를 기준으로 기록하고 앱 크기를 변경하지 않는다.

결정 후 선택한 본문을 확인하고, 페이지 제목·내용 제목·섹션 제목과 보조 정보의 위계를 이어서 검토한다.
본문 정렬·기타 행간·문단 간격과 모든 타이포 위계를 이번 질문 하나로 확정하지 않는다.
SunEditor 내부·CSP·에디터 서식 차이·Sonner는 계속 제외한다.

## 결정

**사용자는 B를 선택했다. DS-015로 16px/32px를 확정하고 공지 상세 읽기 영역에 적용했다.**

## 비교 문서 확인

Playwright 1.57.0 Linux Chromium의 1280·390px에서 문서 표시와 가로 넘침 없음을 확인했다.
A/B 견본의 크기·줄높이, 4개 본문 이미지 전환과 페이지 맥락 이미지 링크를 확인했다.
문서 자체의 확인이며 타이포 앱 적용·전체 콘텐츠 회귀 결과가 아니다.

## DS-015 실제 적용 확인

공지 상세의 읽기 영역에만 기본 크기를 지정했다. 공유 본문 CSS·에디터·다른 페이지의 본문 크기는 변경하지 않았다.
새 프로덕션 프론트에서 한국어·영어 1280·390px의 본문 이미지 4장이 승인 B와 일치했다.
본문 폭·높이, 상대 h2 24px, 명시적 18px, 공지 고유 제목 20px/600 유지도 대조했다.
인사말의 다른 HTMLViewer는 14px를 유지했다. 조사 공지는 확인 후 삭제했다.
[적용 기록](type-density-implementation/measurements.json). 모든 작성자 콘텐츠·배치의 회귀 결과는 아니다.
