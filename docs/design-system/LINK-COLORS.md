# 정보 링크 색과 식별 표시 — DS-011

[현재 DS](index.html) · [견본과 실제 화면 비교](link-colors.html) · [진행 현황](PLAN.md)

DS-009의 정보 링크 계열을 구체화한다. **C-Q5에서 B로 확정했다(DS-011). 앱에 적용하고 표본 화면 확인을 마쳤다.**
주황·중립색의 DS-007~010은 유지한다.

## 왜 변경하는가

**현재 문제:** 기존 정보 링크는 12~14px의 작은 글자로 표시되는 사용처가 있다.
#3c7be4는 흰색에서 4.08:1, neutral-50에서 3.91:1, neutral-100에서 3.74:1로,
[WCAG 2.2 SC 1.4.3 AA의 일반 글자 기준 4.5:1](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)에 못 미친다.
이 기준은 글자와 바탕의 명도 차이를 확보해 대비를 구분하기 어려운 사람도 읽을 수 있게 하는 기준이다.
또한 기존에는 호버해야 밑줄이 나타나므로 기본 상태와 터치 환경에서는 링크 식별이 색에 의존한다.

**변경 이유:** #2867cf는 기존과 비슷한 파랑의 색상각을 유지하면서 상대 휘도를 낮춘 선택이다.
흰색·neutral-50·100에서 각각 5.34:1·5.12:1·4.90:1로 일반 글자 대비 기준을 넘는다.
이 hex만 유일한 해법인 것은 아니며, 기존 인상과 대비 여유를 함께 고려한 값이다.

**기대 효과와 범위:** 농도는 글자를 읽기 쉽게 하고, 항상 보이는 밑줄은 클릭 가능한 글자임을 알려준다.
둘은 서로 다른 문제를 해결한다. 밑줄만 붙인다고 기존 글자/바탕의 대비가 높아지는 것은 아니다.
기존 정보 링크 5곳에 적용하며, 전체 사이트의 접근성 충족이나 모든 링크 상태 해결을 뜻하지 않는다.
주황은 사용자 결정 DS-007에 따라 기존 조합을 유지한다.

## 변경 전 사용처와 비교안

변경 전 `app.css`의 `--color-link: #3c7be4`를 아래 다섯 파일이 `text-link hover:underline`으로 사용했다.

| 사용처 | 맥락 |
| --- | --- |
| [PeopleContactList](../../apps/web/src/routes/$locale/people/-components/PeopleContactList.tsx) | 연락처 설명 속 이메일 링크, 흰 바탕 |
| [PeopleProfileInfo](../../apps/web/src/routes/$locale/people/-components/PeopleProfileInfo.tsx) | 인물 프로필 옆 이메일·홈페이지, 흰 바탕 |
| [Directions](../../apps/web/src/routes/$locale/about/directions/index.tsx) | 안내 문장 속 학부 연락처 링크, 흰 바탕 |
| [CompanyRow](../../apps/web/src/routes/$locale/about/future-careers/-components/CompanyRow.tsx) | 창업 기업 홈페이지, 흰색·neutral-100 교차 행 |
| [Seminar LinkOrText](../../apps/web/src/routes/$locale/community/seminar/$id.tsx) | 세미나의 관련 정보 링크, neutral-50 본문 영역 |

정보 링크는 문장·연락처·부가 정보에서 다른 정보나 외부 주소로 연결하는 글자다.
내비게이션·카드 전체·버튼 링크까지 모두 파랗게 만들거나 밑줄을 붙이는 규칙이 아니다.

현재 파랑은 흰색에서 약 4.08:1, neutral-50에서 3.91:1, neutral-100에서 3.74:1이다.
기존과 가까운 색상각을 유지하고 밝기를 낮춘 **#2867cf**를 제안한다.
이 값은 같은 배경에서 각각 약 5.34:1, 5.12:1, 4.90:1이다.
수치는 불투명 sRGB 조합 계산이며 전체 접근성 충족을 의미하지 않는다.

| 안 | 글자색 | 기본 / 마우스 호버 | 차이 |
| --- | --- | --- | --- |
| 기존 | #3c7be4 | 밑줄 없음 / 있음 | 현재 표현 |
| A | #2867cf | 밑줄 없음 / 있음 | 글자 농도만 조정. 링크 구분 방식은 현재와 동일 |
| B · 추천 | #2867cf | 밑줄 있음 / 있음 | 마우스를 올리지 않아도 클릭 가능한 글자임을 보여줌. 터치 환경에도 같은 단서 |

B의 밑줄은 글자색과 같은 색, 두께 1px·글자와의 간격 2px다. 글자 크기·굵기·주변 배치는 유지한다.
색만 짙게 하면 주변 짙은 설명 글자와 색만으로 구분하기 어려울 수 있어 B를 추천한다.
호버에도 같은 색과 밑줄을 유지한다. 초점은 현재 브라우저/앱 표시를 보존하며, 공통 초점 규칙은 후속 컨트롤 상태 검토에서 다룬다.

## 비교 근거와 범위

DS-010 적용 프로덕션 프론트와 기존 로컬 실 API에서 행정직원 연락처와 창업 기업 목록을 열어
같은 DOM의 `text-link` 글자색과 밑줄만 바꾸고 해당 영역을 캡처했다.
한국어 1280·390px의 두 사용처, 총 4장면에 기존·A·B의 12개 이미지가 있다.
각 장면의 영역 폭·높이·텍스트는 세 안에서 동일했다. 외부 링크를 열거나 데이터를 변경하지 않았다.
[측정 기록](link-comparison/measurements.json).

이는 두 사용처의 비교 자료다. 다른 세 사용처·영어·줄바꿈이 긴 링크·키보드 초점 등 전체 상태 검증은
결정 후 적용 범위에 맞춰 확인한다. 기존 회귀 기준을 갱신하지 않았다.

`--color-link` 값과 위 다섯 사용처의 표시를 B로 적용했다.
HTMLViewer·작성자가 넣은 본문 링크, SunEditor·Sonner, 내비게이션·카드 링크, 다른 직접 지정된 파랑은 이번에 바꾸지 않는다.
오류의 기존 red-600과 위험 행동의 표현도 이번 질문으로 결정하지 않는다.

## 결정 결과

사용자는 B를 선택했다(DS-011). 앱 적용 확인 후 오류·검색/컨트롤 상태로 이어간다.

## 비교 문서 확인

Playwright 1.57.0 Linux Chromium에서 1280·390px 문서를 확인했다.
12개 이미지 전환·로딩, 라디오의 화살표 키 이동, 원본 크기, 견본의 기본/호버 표현과 문서 링크를 확인했다.
문서 페이지의 가로 넘침은 없고 넓은 표·원본 이미지는 해당 영역 안에서 스크롤한다.
누적 DS의 입력 초점 견본과 DS-010 결정 상태도 확인했다.

## DS-011 적용 확인

한국어 연락처·기업 목록 1280·390px의 4개 영역 이미지가 승인한 B와 일치했다. 같은 두 사용처는 영어 두 폭에서도 기본·호버·키보드 초점을 확인했다.
프로필과 찾아오는 길은 한국어 데스크톱의 색·밑줄·호버·키보드 초점을 확인했다.
세미나 시드에는 링크 주소가 없어 소스 클래스만 대조했고 해당 링크의 실제 렌더 확인은 남는다.
[적용 원자료](link-implementation/measurements.json). 긴 URL 전체와 모든 콘텐츠를 검증한 것은 아니다.
외부 링크 이동·데이터 저장 없이 새 프론트 프로덕션 빌드와 기존 로컬 실 API로 확인했다. 전체 회귀는 아니다.
