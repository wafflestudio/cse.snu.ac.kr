# 디자인 시스템 방향과 후속 검토 기준

[진행 현황](PLAN.md) · [결정 기록](DECISIONS.md) · [조사 분류](CLASSIFICATION.md)

## 결정된 출발점

| 결정 | 이후 작업에 적용할 기준 |
| --- | --- |
| DS-001. 정체성 보존 | 어두운 큰 면·주황·원과 선·접힌 모서리를 이어간다. |
| DS-002. 사용성 개선을 위한 변경 | 기존 인상과 정보 구조를 유지하며 색·서체·간격·배치를 조정할 수 있다. 구체적인 변경안은 적용 전에 화면으로 비교한다. |
| DS-003. 작업 환경 | 공개 기능은 모바일을 지원하고, 행정실 편집·관리는 데스크톱 중심으로 설계한다. |
| DS-004. 주요 실행의 강조 | 추가·저장·게시·예약은 짙은 중립색을 기본으로 한다. 주황의 그래픽·선택 표시는 유지한다. 최종 값·상태·배경별 예외는 후속 비교한다. |
| DS-005. 문구 | 짧은 행동명과 차분한 존댓말로 실제 행동·대상·결과를 드러낸다. ‘변경사항 저장’처럼 구분에 필요한 의미는 생략하지 않는다. |
| DS-006. 본문 서체 | 공유 본문 CSS의 기본 서체를 Pretendard Variable로 연결한다. 크기·행간·밀도는 후속 비교한다. |
| DS-007. 주황·흰 글씨 유지 | 브랜드 주황 #ff6914와 기존 흰 글씨 조합을 유지한다. 대비 미달은 알려진 한계로 기록하고 개선은 보류한다. |

아래는 이 결정에서 출발한 **역할과 검토 순서의 제안**이다. 승인된 토큰·컴포넌트 규칙이 아니다.
실제 화면 대조와 행동 강조의 두 안은 [HIERARCHY.md](HIERARCHY.md)와 [비교 페이지](hierarchy.html)에 있다.
주요 실행은 A로, 문구는 짧은 행동명과 차분한 존댓말로 결정했다. 문구의 비교 근거와 적용 경계는 [COPY.md](COPY.md)에 있다.

## 정보 위계와 표현의 역할 제안

| 맥락 | 우선 전달할 정보 | 표현의 역할과 다음 비교 |
| --- | --- | --- |
| 메인·카테고리 | 학부의 인상, 탐색할 영역 | 큰 어두운 면과 기하학 표현을 유지한다. 큰 제목과 소개문·탐색 카드의 위계를 설명하고 일반 본문의 밀도와 구분한다. |
| 일반 페이지·게시물 | 현재 위치, 문서의 제목, 읽을 내용, 보조 정보 | 페이지 종류를 나타내는 제목과 개별 게시물 제목을 구분한다. 본문·날짜·태그·관련 이동의 강조 수준을 실제 긴 글에서 비교한다. |
| 선택형 상세·목록 | 현재 선택, 선택 가능한 항목, 선택의 결과 | 원과 선·접힌 모서리가 관계·선택·강조 중 무엇을 전달하는지 정리한다. 모양만 같다고 페이지 이동과 값 선택을 한 패턴으로 합치지 않는다. |
| 행정실 편집·관리 | 입력할 항목, 현재 상태, 오류, 저장 결과 | 데스크톱에서 읽기 순서와 입력·수정·저장 흐름을 우선한다. 키보드 초점과 오류 안내는 모바일 수요와 관계없이 검토한다. |
| 일반 이용자의 예약 | 대상·날짜·시간, 선택 상태, 실행 결과 | 모바일에서도 예약 흐름을 검토한다. 입력 폼이라는 이유로 행정실 관리 화면의 지원 범위에 넣지 않는다. |

일반 페이지·선택형 상세·데스크톱 편집의 실제 비교는 HIERARCHY.md에 있다.
H-01~H-03은 구현을 대조할 작업 가설로 사용한다. 사용자가 역할표 전체나 개별 크기·배치를
별도로 승인한 것으로 처리하지 않는다. 구체적인 기반·컴포넌트 비교에서 필요한 부분을 검증한다.

## 색·그래픽·문구를 구체화할 때의 질문

- **주황:** 주요 실행은 DS-004에 따라 짙은 중립색을 기본으로 한다. 주황의 장식·선택·필수 표시는
  각각의 문맥으로 설명하며, 정체성을 유지하면서 작은 글자와 배경의 조합을 별도로 정한다.
- **원과 선·접힌 모서리:** 관계·선택·강조를 어떤 사용처에서 나타내는가?
  보존된 모양의 의미를 설명하고 예외의 범위를 기록한다.
- **정보 밀도:** 메인 표현, 읽는 본문, 행정실 폼의 밀도를 다르게 둘 이유가 있는가?
  본문 서체 연결과 가용 폭이 달라질 때 글줄과 간격도 함께 비교한다.
- **문구:** DS-005에 따라 실제 행동을 드러낸다. 확인·오류에서 설명하는 손실·다음 행동은
  구현과 일치해야 한다. 아직 확인하지 못한 저장 결과·복구 가능성은 단정하지 않는다.

## 기반·컴포넌트 검토에 넘기는 예외

| 경계 | 후속 적용 기준 |
| --- | --- |
| 상단 제목 | 구역 이름인 공지와 대상 이름인 연구실 상세를 구분한다. 모든 페이지에 같은 제목 단계를 추가하지 않는다. |
| 접힌 모서리 | 주황 선택 목록과 어두운 연락처 요약은 같은 모양의 다른 역할이다. 전역적으로 ‘선택됨’이라는 뜻을 부여하지 않는다. |
| 행동 강조 | DS-004가 기본이다. 위험 행동과 어두운 배경 위 행동은 별도 상태·대비 비교가 필요하다. |
| 읽기와 편집 | 기본 서체를 함께 연결하더라도 본문 폭·에디터 패딩·툴바가 달라 줄바꿈까지 동일하지는 않다. 작성자가 지정한 스타일과 기본 스타일을 구분한다. |
| 문구와 동작 | 편집 취소·단건/반복 취소·오류·처리 중 문구는 실제 흐름과 함께 검증한다. 문장 교체만으로 사용성 문제를 해결했다고 보지 않는다. |

방향 단계의 사용자 선택은 DS-001~DS-005로 연결했다. 본문 서체 연결은 DS-006으로 적용·확인했다.
이후 역할별 색·대비와 초점, 타이포 위계, 아이콘과 조작 영역, 공개 배치·간격을 다룬다.
주황 배경/흰 글씨는 DS-007로 유지·개선 보류를 결정했다. 현재 비교는 [입력 예시·보조 버튼·초점](neutral-focus.html)이다. 기능 버그는 기록만 남기고, SunEditor 내부·CSP·에디터 서식 차이와 Sonner 수정은 사용자 요청에 따라 제외한다.

## 지원 범위가 조사 결과에 미치는 영향

P-01 서체, P-02 대비, P-03 초점과 공개 화면의 P-04·P-05 넘침은 계속 검토한다.
P-06의 모바일 교수 폼·첨부 행 넘침은 기록을 보존하되 v1의 필수 개선 대상에서 제외한다.
데스크톱에서 같은 폼을 쓰기 어렵거나 공용 컴포넌트 변경이 공개 모바일 기능에 영향을 주면
그 문제는 각각의 지원 범위에서 다시 검증한다.

모바일 편집을 차단하거나 별도 안내를 추가하는 것은 이번 결정에 포함되지 않는다.
데스크톱 최소 지원 폭, 공개 화면의 배치 전환값, 구체적인 서체·색·크기는 후속 비교에서 정한다.
