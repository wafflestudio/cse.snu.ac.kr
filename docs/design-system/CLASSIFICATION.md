## 이번 분류의 결론

현재 사이트에는 공통 틀과 반복되는 표현이 이미 있다. 새 시스템의 출발점은 이들의 **역할·선택 기준·예외를 설명하는 것**이다.
동시에 서체 연결, 대비, 키보드 초점, 화면 넘침은 실제 사용에 영향을 주므로 기반 규칙과 함께 해결해야 한다.
값을 정리하면서 화면을 수정하는 것 자체는 필요할 수 있다. 다만 변경마다 해결할 문제와 영향을 받는 사용처를 연결해야 한다.

아래 분류는 `d1baf83c`의 앱을 조사한 1-1~1-3 자료에 대한 해석이다. 새 디자인 승인이나 수정 완료를 뜻하지 않는다.
1-4에서는 앱과 기준 이미지를 변경하지 않았다. 저자의 의도를 확인할 수 없는 차이는 ‘우연’이라고 확정하지 않는다.

| 분류 | 판별 기준 | 다음 행동 |
| --- | --- | --- |
| C. 반복 규칙 후보 | 여러 사용처에서 같은 역할과 구조가 반복됨 | 사용 기준과 예외를 제안하고 대표 화면에서 검증 |
| P. 확인된 문제 | 실제 렌더·측정에서 읽기/조작/폭 또는 서체 연결 문제가 확인됨 | 해결 조건부터 정하고 수정안을 비교 |
| D. 이유를 확인할 차이 | 값·동작은 다르지만, 차이를 없애야 한다는 근거가 부족함 | 같은 역할끼리 비교한 뒤 유지/통일 결정 |
| E. 예외 후보·별도 책임 | 다른 목적이나 콘텐츠 제약으로 공통 규칙과 구분할 필요가 있음 | 예외의 범위와 지켜야 할 공통 조건을 기록 |
| U. 추가 확인 | 정적 의심, 데이터 문제, 미수집 상태 또는 검증 환경의 한계 | 필요한 표본만 보충. 확인된 결함이나 디자인 선택으로 넘기지 않음 |

빈도는 중요도의 증거가 아니며, ‘반복 규칙 후보’의 현재 수치도 확정값이 아니다.
문제와 특징이 같은 요소에 공존할 수 있다. 예를 들어 주황의 정체성은 C-02, 작은 주황 글자의 대비는 P-02다.

## 1-5에서 함께 볼 세 가지 질문

[화면 모음](review.html)은 모두 변경 전 이미지다. 아래는 **권장 방향과 선택에 따른 범위**이지, 확정된 디자인안이 아니다.
새 색·서체 크기·컴포넌트 모양은 3~4단계에서 실제 적용 비교를 보고 정한다.

| 질문 | 권장 출발점 | 다른 선택을 하면 달라지는 범위 |

## 권장 실행 순서와 변경 근거

1. **방향:** J-01~J-03을 검토하고 보존 범위·변경 범위·지원 작업을 기록한다.
2. **기반:** P-01 서체 연결과 P-04~P-06 배치 조건을 먼저 비교한다. 서체와 폭이 글줄·높이·간격 평가를 바꾸기 때문이다.
3. **색·크기·형태:** P-02 대비와 D-01~D-05를 역할별로 검토한다. C/E의 구분을 규칙과 예외로 구체화한다.
4. **상태·문구:** P-03과 D-06~D-07, U-01을 대표 폼·탐색·피드백 흐름에서 검증한다. 기본 모양 확정 후에도 상태 검토를 빠뜨리지 않는다.
5. **확장·통합:** 합의한 규칙을 사용처에 적용하고 필요한 미수집 상태를 채운다. U-04의 기존 실패와 의도된 시각 변경은 별도로 판정한다.

실제 적용 전에는 `연결된 ID → 해결할 문제 → 선택안과 이유 → 영향받는 사용처 → 검증 결과`를 결정 기록에 남긴다.
예를 들어 ‘숫자가 비슷하니 간격을 합쳤다’만으로는 부족하다. ‘같은 역할의 버튼 묶음에서 정렬을 맞추기 위해 변경했고,
폼과 모달에서 확인했다’처럼 설명할 수 있어야 한다. 이 기준으로 이전 tmp 작업의 일부도 필요할 때 다시 평가한다.

이번 작업은 기존 자료와 소스의 분류·검토물 작성이다. 앱 회귀 테스트를 새로 실행하거나 미확인 문제를 해결했다고 처리하지 않았다.
