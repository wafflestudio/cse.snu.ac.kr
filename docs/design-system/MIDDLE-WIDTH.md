# 중간 폭의 공개 화면 — L-Q2 비교

[누적 DS](index.html) · [실제 A/B 비교](middle-width.html) · [계획](PLAN.md)

## 확정·적용과 미확정의 경계

DS-022 모바일 푸터 줄바꿈은 앱에 적용했다. 한·영 20개 상태의 배치와 대표 이미지 6장이 승인 견본과 일치했다.
[실제 적용](layout.html). 중간 폭 배치는 아래 두 안 모두 **브라우저 안에서만 만든 비교 견본이며 앱 미적용**이다.
공개 화면부터 비교한다. 편집·관리의 필드 배치와 지원 폭은 아직 새로 결정하지 않았다.

## 문제와 변경 이유

현재 640px부터 데스크톱 배치가 켜지고 body의 최소 폭은 1200px이다.
768·1024px에서도 문서가 1200px로 펼쳐져 페이지를 가로로 움직여야 한다.
본문뿐 아니라 좌측 상시 메뉴와 오른쪽 보조 탐색이 같은 공간을 차지한다. 최소 폭만 없애는 것으로는 충분하지 않다.

일반 페이지는 바깥 좌측 내비 100px, 본문 왼쪽 여백 100px, 오른쪽 탐색 자리 360px를 사용한다.
이대로 768px에 맞추면 본문은 약 208px, 1024px에서는 약 464px밖에 남지 않는다.
따라서 **탐색을 접는 전환과 콘텐츠 자체의 배치 전환을 구분**하는 방식을 비교했다.
기존 색·서체·원/선 그래픽을 새로 디자인하려는 결정은 아니다.

**추천 이유:** B는 페이지 가로 넘침을 해소하면서, 충분한 폭에서 기존에 보이던 정보와 보기 선택을 더 많이 유지한다(DS-016).
1200px는 현재 데스크톱이 요구하는 최소 폭을 기준으로 잡은 첫 제안이다. 임의로 새 장치 종류를 구분하는 값이 아니다.
1024px는 기존 7일 달력과 교과목 구성이 들어가는 폭에서 비교한 첫 콘텐츠 전환값이다.
모든 컴포넌트를 1024px로 통일하자는 뜻은 아니다. 달력만 더 이르게 전환하는 세분화는 이번 제안에 포함하지 않았다.

## 실제 비교에서 확인한 것

- 학부 소개·교과목 카드 보기 URL·예약을 한·영 768·1024px에서 비교했다. 원래 문서 폭은 1200px, A/B는 모두 각 화면 폭과 같았다.
- A는 예약 3일 표시와 다음 3일 이동을, B는 768px에서 3일·1024px에서 7일 표시와 동일한 날짜 이동을 확인했다. 예약 생성·편집은 하지 않았다.
- A는 상단 메뉴 열기/닫기와 열린 상태의 본문 스크롤 제한을 확인했다. **B의 1024px 메뉴 스크롤 제한은 미검증**이다. 현재 하나의 JS 폭 조건이 여러 역할에 공유돼 있어 실제 구현 때 분리해야 한다.
- B의 교과목 카드 보기와 보기 선택 노출은 확인했다. 목록 전환·여러 카드 스크롤·다양한 긴 데이터는 적용 시 확인할 조건이다. 기존 카드의 HTML 표기 문제(Q-14)는 그대로다.
- A는 영어 390·640·1199·1200·1280px의 소개 경계와 768px 메인·학사 카테고리·교수 목록도 보았다. 각 문서 폭은 화면 폭과 같았다. B의 이 추가 화면·경계 전체는 아직 검증하지 않았다.
- 전후 이미지는 같은 뷰포트의 첫 900px다. 기존 화면의 오른쪽이 잘리는 것은 가로로 넘친 상태를 그대로 보여주는 것이다. 전체 문서·모든 콘텐츠를 검증한 스크린샷이 아니다.

[현재/A 측정](middle-width-comparison/measurements.json) · [B 측정](middle-width-comparison/adaptive-measurements.json).
로컬 프로덕션 앱의 CSS 미디어 조건과 기존 반응형 JS 판정을 브라우저 안에서 임시 조정했다.
B는 데이터 영역의 기존 데스크톱 스타일을 해당 폭에서 복원했다. 앱 소스·백엔드·기존 기능 로직은 변경하지 않았다.
이 비교는 방향 판단용이며 검증을 마친 구현으로 취급하지 않는다.

## 승인 이후의 적용 경계

1. 공개 공통 틀의 탐색·여백과 콘텐츠별 전환 조건을 별도로 정의한다. Tailwind `sm` 전역 값 하나를 바꿔 모든 화면을 한꺼번에 이동시키지 않는다.
2. 루트/오류 화면·헤더·좌측/모바일/보조 탐색·본문·푸터를 함께 맞추고 메뉴 열림의 스크롤 제한을 확인한다.
3. 교과목 보기·예약 표시/날짜 이동·페이지 이동 등 기존 JS 분기와 CSS 표시가 일치하는지 확인한다. 이번 작업으로 유발되는 배치 연결만 다루며 별도 기능 버그는 후속에 기록한다.
4. 메인·카테고리·읽는 글·인물·목록·표의 역할별 기존 구성을 대조한다. 제시하지 않은 새 모양이 필요하면 추가 비교한다.
5. 이미지 `sizes`의 현재 640px 조건도 해당 이미지의 실제 표시 폭에 맞춘다. 검토용 이미지에서는 기존 sizes를 유지했으므로 아직 연결 완료가 아니다.
6. 한·영 639/640·1023/1024·1199/1200 경계와 390·768·1280을 확인한다. 관리·편집 필드에 대한 일괄 모바일 확대는 포함하지 않는다. SunEditor·Sonner는 제외한다.
