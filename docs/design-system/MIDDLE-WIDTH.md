# 중간 폭의 공개 화면 — DS-023 적용

[누적 DS](index.html) · [실제 A/B 비교](middle-width.html) · [계획](PLAN.md)

## 확정·적용과 미확정의 경계

**L-Q2의 B안을 승인받아 DS-023으로 앱에 적용했다.** 공통 틀은 1200px, 교과목·예약은 1024px에서 전환한다.
[실제 적용 이미지](middle-width.html) · [162개 공개 상태 측정](middle-width-implementation/measurements.json).
편집·관리의 필드 배치와 최소 지원 폭은 이번 결정에 포함하지 않았다.

## 문제와 변경 이유

변경 전에는 640px부터 데스크톱 배치가 켜지고 body의 최소 폭은 1200px이다.
768·1024px에서도 문서가 1200px로 펼쳐져 페이지를 가로로 움직여야 한다.
본문뿐 아니라 좌측 상시 메뉴와 오른쪽 보조 탐색이 같은 공간을 차지한다. 최소 폭만 없애는 것으로는 충분하지 않다.

일반 페이지는 바깥 좌측 내비 100px, 본문 왼쪽 여백 100px, 오른쪽 탐색 자리 360px를 사용한다.
이대로 768px에 맞추면 본문은 약 208px, 1024px에서는 약 464px밖에 남지 않는다.
따라서 **탐색을 접는 전환과 콘텐츠 자체의 배치 전환을 구분**하는 방식을 비교했다.
기존 색·서체·원/선 그래픽을 새로 디자인하려는 결정은 아니다.

## 두 안

| 비교 | A — 기존 모바일 구성을 통째로 연장 | B — 탐색과 콘텐츠 전환을 분리 (승인·적용) |
| --- | --- | --- |
| 공통 틀 640~1199px | 상단 메뉴 버튼, 좌우 상시 탐색 숨김, 좁은 화면용 여백 | A와 동일 |
| 1200px 이상 | 기존 데스크톱 구성 | 기존 데스크톱 구성 |
| 소개 책자 | 세로 나열 | 기존 가로 나열 유지. 두 권 227px씩+24px 간격이 640px에도 들어감 |
| 교과목 640~1023px | 기존 모바일 목록형 | 기존 모바일 목록형 |
| 교과목 1024~1199px | 목록형만 표시 | 기존 목록/카드 선택 유지 |
| 예약 640~1023px | 기존 3일 보기·3일 이동 | 기존 3일 보기·3일 이동 |
| 예약 1024~1199px | 3일 보기·3일 이동 | 기존 7일 보기·7일 이동 |
| 장점 | 기존 좁은 화면 구성으로 단순하게 통일 | 공간이 충분한데 정보를 줄이는 변경을 피함 |
| 비용·한계 | 넓은 태블릿에서도 정보량 감소·빈 공간 증가 | 컴포넌트별 전환 조건과 CSS/JS 일치를 관리해야 함 |

**선택 이유:** B는 페이지 가로 넘침을 해소하면서, 충분한 폭에서 기존에 보이던 정보와 보기 선택을 더 많이 유지한다(DS-016).
1200px는 현재 데스크톱이 요구하는 최소 폭을 기준으로 잡은 첫 제안이다. 임의로 새 장치 종류를 구분하는 값이 아니다.
1024px는 기존 7일 달력과 교과목 구성이 들어가는 폭에서 비교한 첫 콘텐츠 전환값이다.
모든 컴포넌트를 1024px로 통일하자는 뜻은 아니다. 달력만 더 이르게 전환하는 세분화는 이번 제안에 포함하지 않았다.

## 확정한 규칙과 구현 경계

- 공통 탐색·페이지 틀·메인·카테고리·푸터: 1200px 미만에서는 기존 좁은 화면 구성을 사용한다. 1200px 이상은 기존 데스크톱 구성을 유지한다.
- 교과목·예약: 1024px 미만은 목록형·3일 표시/이동, 이상은 기존 목록/카드 선택·7일 표시/이동을 유지한다.
- 소개 책자 가로 배치, 인물 그리드, 목록, 페이지 번호 개수 등 공간에 들어가는 기존 콘텐츠 전환은 유지한다. 모든 `sm`을 바꾸지 않는다.
- 가로 거터는 `.page-gutter-x` 한 곳에서 관리한다. Tailwind `shell`(75rem)과 메뉴 JS 판정, 기존 `lg`(64rem)와 교과목·달력 JS 판정을 각각 연결했다.
- 소개 사진·메인 중요 공지 이미지의 sizes를 실제 표시 폭에 맞췄다. 자체 콘텐츠 전환이 그대로인 이미지 조건은 유지했다.
- DS-022 푸터 줄바꿈은 좁은 틀을 사용하는 1200px 미만으로 함께 확장했다. 1200px 이상은 기존 한 줄 표시다.
- SunEditor·Sonner·작성 기능 로직은 변경하지 않았다. 편집 필드의 모바일 최적화는 포함하지 않는다.

## 적용 검증

새 프로덕션 빌드 + 기존 로컬 실 API, Playwright 1.57.0 Linux Chromium에서 확인했다.

- 소개·교과목·예약의 한·영 768/1024px **실제 이미지 12장이 승인 B 견본과 바이트까지 일치**했다.
- 공개 9유형(소개·교과목·예약·메인·카테고리·교수·공지·뉴스·연구실) × 2언어 × 9폭(390/639/640/768/1023/1024/1199/1200/1280), 총 162개 상태를 실측했다.
- 소개에서 639/640, 1023/1024, 1199/1200 경계와 1280px의 메뉴 노출·열기/닫기·본문 스크롤 제한을 확인했다.
- 예약은 1023/1024/1199/1200px에서 표시 열 수와 다음/이전 날짜 이동이 3일/7일로 일치했다. 교과목의 리사이즈·목록/카드 전환도 확인했다. 이 두 회귀 검사는 E2E에 남겼다.
- 공통 최소 폭 문제는 해소됐지만 **모든 콘텐츠의 넘침이 해결된 것은 아니다.** 영어 메인 390px는 문서 폭 420px, 영어 공지 1023/1024px는 1054px로 나타났다. 긴 선택 항목의 배치 문제이며 별도 비교한다. 문서 폭이 맞더라도 내부 겹침까지 없다고 단정하지 않는다.
- 다수 카드 스크롤·긴 임의 데이터·큰 글자·예약 생성 모달·전체 회귀는 이번 표본 검증과 구분한다. 기존 카드 HTML 표기(Q-14)도 그대로 남긴다.

[실제 적용 측정](middle-width-implementation/measurements.json).
승인 전 [기존/A 측정](middle-width-comparison/measurements.json)과 [B 측정](middle-width-comparison/adaptive-measurements.json)은 브라우저 안에서 만든 방향 비교 기록으로 보존한다.
실제 적용 이미지는 별도 디렉터리에 저장해 승인 견본과 구분했다.

모바일 390px·데스크톱 1280px의 9유형 × 2언어, 전체 페이지 이미지 36장을 직전 커밋 `088fd3c7`의 새 빌드와 비교했다. 모두 바이트까지 일치했다. [경계 밖 회귀 기록](middle-width-implementation/edge-regression.json). 영어 메인 390px의 넘침도 기존과 동일하며 이번 변경으로 새로 생긴 것이 아니다.
