## 확정·적용한 기준

- DS-016: 명확한 문제가 없으면 기존 그림·크기·위치를 유지한다.
- DS-017: 헤더 검색은 기본 #737373 → 호버 #404040으로 진해진다.
- DS-018: 헤더 검색 24×30, 세미나·모바일 검색 실행 24×24px. 그림은 유지하고 입력칸의 폭만 2~2.5px 줄인다. 한·영 8장면의 실제 앱이 승인 견본과 일치했다.

[DS-018 적용 기록](icon-target-implementation/measurements.json). 가장자리의 버튼 판정·호버·Tab 초점과 긴 입력문의 배치도 확인했다.

## I-Q3 — DS-019 적용: 교과목 카드 화살표의 키보드 초점

**수정 전 문제:** 데스크톱 카드형 교과목의 좌우 버튼은 평소 `opacity: 0`이고 행에 마우스를 올려야 보인다.
키보드로 Tab 이동하면 버튼에 초점이 도달하지만 마우스가 행 밖에 있을 때 계속 투명하다. 버튼뿐 아니라 그 초점 표시도 같이 숨겨진다.
한국어·영어 1280px에서 재현했다. 모바일은 기존 목록형을 사용하므로 이 카드 행이 표시되지 않는다.

**변경 이유:** [WCAG 2.4.7 설명](https://www.w3.org/WAI/WCAG22/Understanding/focus-visible.html)은 키보드 초점 위치가 보이는 방식을 요구한다.
이번 문제는 초점이 실제로 이동한 버튼 전체가 투명해진다는 점이다. 특정 두께의 새 외곽선을 요구하는 것이 아니다.

**확정·적용:** 행 안에 키보드 초점이 들어왔을 때도 기존 마우스 호버와 같이 양쪽 화살표를 표시한다.
포커스된 버튼은 기존 브라우저 초점 표시로 구별한다. 평소 숨김, 마우스 호버, 주황 #ff6914, 그림 44px, 클릭 영역·카드 배치·스크롤 동작은 유지한다.
행 밖으로 초점과 마우스가 모두 나가면 기존처럼 숨긴다. 사용자가 입력 초점 외곽선을 제거한 DS-012와는 별개이며 입력 필드는 변경하지 않는다.

**비교:** [한국어·영어 실제 화면](icon-focus.html). 실제 Tab 초점 상태에서 행의 양쪽 버튼 불투명도만 임시로 바꾼 캡처다.
DS-019로 앱 CSS에 반영했고 [실제 적용 기록](course-focus-implementation/measurements.json)의 한·영 기본/초점 이미지가 원본/승인 견본과 일치했다. 행 안 Tab 이동·행 밖 복귀·호버도 확인했다. 문서 견본에서 `focus-within`에 따른 표시·복귀를 직접 확인할 수 있다.

**영향·한계:** 순수 표시 변경이다. 화살표의 접근 가능한 이름 누락은 Q-13으로 기록했고 별도 컴포넌트 단계에서 다룬다.
현재 로컬 데이터는 카드 한 개라 스크롤 이동량을 검증한 것은 아니다. 주황 아이콘 대비 및 전체 버튼 상태의 적합성을 선언하지 않는다.

## 결정 상태

I-Q3는 DS-019로 적용·확인했다. 사용자의 통일 요청에 따라 [공통 초점 모양 F-Q1](FOCUS.md)을 이어서 검토한다.

## 다음 범위

F-Q1 결정 후 연구실 자료 아이콘 등 아직 실측하지 않은 단독 링크의 상태를 확인한다.
첨부·폼 아이콘의 이름과 결합 상태, 브랜드 주황이 쓰인 조작의 대비 등은 4단계에 추적하며 완료로 간주하지 않는다.

## 검토 문서 확인

1280·390px에서 누적 DS·검색 클릭 영역·키보드 비교 문서의 가로 넘침과 내부 링크, 한·영 이미지 전환을 확인했다.
문서의 Tab 견본은 시작 → 왼쪽 → 오른쪽 → 행 밖의 순서로 초점이 이동하며 양쪽 화살표 표시·숨김이 반응했다. 마우스 호버 표시와 이탈 복귀도 확인했다.
