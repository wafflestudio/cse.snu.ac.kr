# 색 역할 — 주황과 작은 글자의 첫 비교

[현재 DS 전체 보기](index.html) · [현재 위치](PLAN.md) · [비교 견본](colors.html) · [기존 색 조사](ROLE-AUDIT.md)

3-2의 첫 질문 C-Q1이다. **DS-007 결정: 기존 주황 #ff6914 배경과 흰 글씨를 유지한다. A·B 모두 미채택이며 주황 관련 앱 색상 변경은 없다.**
아래 두 안과 추천 이유는 첫 제안의 기록이며 현재 적용할 결정이 아니다.
전체 팔레트·상태를 한 번에 확정하지 않고, 보존하기로 한 주황과 작은 글자의 조합부터 정한다.

## 관찰과 근거

- [Tag](../../apps/web/src/components/ui/Tag.tsx)의 13px 흰 글자/주황 면, 주황 글자/흰 면은 각각 2.88:1이다.
  테두리 태그의 호버는 흰 글자/주황 면으로 전환한다.
- [SelectionList](../../apps/web/src/components/feature/selection/SelectionList.tsx)의 선택된 글자는
  #fafafa/주황 면으로 2.76:1이다. 크기는 모바일 11px, sm 13px, lg 14px다.
- [CornerFoldedRectangle](../../apps/web/src/components/ui/CornerFoldedRectangle/style.module.css)의
  주황 면과 접힌 모서리, [app.css](../../apps/web/src/app.css)의 주황 #ff6914를 기준으로 비교했다.
- 기존 대비 조사의 기준·수치는 [contrast.json](measurements/contrast.json), 새 후보 계산은
  [color-candidates.json](measurements/color-candidates.json)에 있다. 불투명 sRGB 조합이며 테두리·초점·전체 접근성을 판정한 값은 아니다.

## 두 안

| 역할 | 현재 | A · 추천 | B |
| --- | --- | --- | --- |
| 채운 태그의 면 / 글자 | #ff6914 / #ffffff, 2.88:1 | #ff6914 / #171717, 6.22:1 | #b54708 / #ffffff, 5.43:1 |
| 선택된 면 / 글자 | #ff6914 / #fafafa, 2.76:1 | #ff6914 / #171717, 6.22:1 | #b54708 / #ffffff, 5.43:1 |
| 흰 면 위 주황 글자 | #ff6914, 2.88:1 | #b54708, 5.43:1 | #b54708, 5.43:1 |
| 장식 주황 | #ff6914 | 유지 | 유지 |

A는 선명한 주황 면을 유지하면서 글자를 짙게 한다. B는 흰 글자를 유지하는 대신 글자가 있는 주황 면을 어둡게 한다.
작은 주황 글자는 두 안 모두 더 짙은 주황을 쓴다. A가 DS-001의 주황 면 보존에 더 가깝다고 판단해 추천한다.
새 #b54708은 이번 견본의 후보이며 확정 토큰이 아니다. 기존 main-orange-dark #e65817나 이전 브랜치를 정답으로 가져오지 않았다.

## 견본의 성격과 적용 경계

- colors.html은 소스 기반 HTML 견본이다. 실제 앱 스크린샷이나 React 컴포넌트 통합 검증으로 표시하지 않는다.
  태그 높이·패딩·13px/500, 선택 항목 40px·반응형 글자 크기를 사용했고, 접힌 모서리 CSS는 실제 파일을 읽는다.
  카드 폭과 주변 설명은 검토용 배치다. 선택 목록 전체의 그리드·주변 페이지는 재현하지 않았다.
- 비교 대상은 밝은 바탕의 Tag와 SelectionList에 있는 주황 텍스트/면 조합이다.
  주황을 전역 치환하거나 CornerFoldedRectangle의 다른 사용처를 자동으로 바꾸지 않는다.
- DS-004에 따라 저장·게시·예약 등 주요 실행은 짙은 중립색 기본이다. 이 질문에 주황 주요 버튼을 다시 승인받는 의미는 없다.
- 테두리 태그 기본/호버를 함께 보여준다. 채운 태그의 호버·삭제 아이콘·비활성 등 전체 상태는 선택 후 적용할 때 같은 원칙으로 대조한다.
  키보드 초점과 선택 표시의 비색상 단서, 보조 글자·입력 예시·링크·위험 행동·어두운 배경은 3-2의 후속 검토다.
- SunEditor 내부·CSP·에디터 서식 차이와 Sonner는 제외한다. 발견한 기능 버그는 메모만 남긴다.

견본은 Linux Chromium에서 1280·768·390px 렌더, 페이지 가로 넘침 없음, 태그 호버 색을 확인했다. 앱 통합 검증은 아니다.

## 첫 제안의 질문 — DS-007로 종료

**C-Q1: A처럼 기존의 밝은 주황 면을 유지하고, 그 위 글자에는 짙은 중립색을 사용하는 방향으로 갈까?**
흰 바탕의 작은 주황 글자는 #b54708처럼 더 짙게 나눈다. 흰 글자를 유지하는 인상이 더 중요하다면 B가 대안이다.
선택 후 해당 사용처에 적용하고 화면을 확인한다. 이어서 남은 색·초점 조합을 비교한다.

## 첫 제안 검토 후 확인

사용자는 A·B 모두 마음에 들지 않는다고 답하고 기존 주황 바탕/흰 글씨의 접근성 문제를 질문했다.
기존 #ff6914/#ffffff의 대비는 2.8835:1로, [WCAG 2.2 SC 1.4.3 AA](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)의 일반 글자 4.5:1과 큰 글자 3:1에 모두 미달한다.
현재 11~14px 태그·선택 글자는 일반 글자에 해당한다. 브랜드색이라는 이유로 일반 UI 글자에 로고 예외가 적용되지는 않는다.
이 판정이 첫 B의 #b54708을 써야 한다는 뜻은 아니다. 이후 사용자는 DS-007로 주황 #ff6914 고정과 A의 검은 글자 제외를 명확히 했다.

## 주황 고정 후 검토한 접근 — 모두 이번 적용에서 제외

- 흰 글자 주변에 충분히 짙고 연속적인 외곽선·halo를 두어 국소 대비를 확보할 수 있다([W3C G18](https://www.w3.org/WAI/WCAG22/Techniques/general/G18)). 연한 그림자 하나만으로 충족한다고 보지 않으며 실제 렌더 확인이 필요하다. 작은 한글의 인상과 획 간격에도 영향을 줄 수 있다.
- 주황 면과 글자를 별도 영역에 배치하면 브랜드색을 유지하며 글자/배경 조합을 달리할 수 있다. 컴포넌트 배치 변경이므로 별도 견본 검토가 필요하다.
- 고대비 대체 표현을 제공하는 방법도 있다([W3C G174](https://www.w3.org/WAI/WCAG22/Techniques/general/G174)). 접근 가능한 전환 수단, 동일한 정보·기능 및 목표 수준을 충족하는 대체 버전이 필요하다. 새 기능이므로 현재 구현하지 않는다.
- 기존 조합을 유지하고 2.88:1 대비 미달을 알려진 한계로 남기는 우선순위 선택도 가능하다. 접근성 충족이나 해결로 표시하지 않는다. 사용자가 기존 조합 유지를 결정해 개선은 보류했다.

같은 두 색과 평면 표현을 그대로 유지하면서 대비 수치만 높이는 방법은 없다. 크기·굵기·아이콘 추가만으로 이 글자 대비 미달을 해결했다고 처리하지 않는다.

## C-Q2: 입력 예시·보조 버튼·초점

> 현재 규칙: 입력 예시·보조 버튼 색은 유지한다. 추가 초점 외곽선은 DS-012로 철회했다. 아래 비교·측정은 DS-008 당시 기록이다.

[현재 / 제안 견본](neutral-focus.html). **DS-008로 승인했고 공용 Text·TextArea·Button secondary에 적용했다.**
주황 조합 결정 이후의 다음 단위로 세 가지 중립색 역할을 묶어 검토한다.

| 역할 | 기존 → 제안 | 비교 배경·상태 |
| --- | --- | --- |
| 입력 예시 | #d4d4d4 → #737373 | 흰 바탕 1.48 → 4.74:1, TextList의 #fafafa에서도 제안 4.54:1 |
| 보조 버튼 글자 | #737373 → #525252 | #f5f5f5 기본 4.35 → 7.17:1, #e5e5e5 호버 3.76 → 6.20:1 |
| 입력 초점 | outline 없음 → #404040 2px, offset 2px | 밝은 바탕의 Text·TextArea에 :focus-visible. 배치 크기를 바꾸지 않음 |

입력 예시는 [form/Text](../../apps/web/src/components/form/Text.tsx)와 [TextArea](../../apps/web/src/components/form/TextArea.tsx)의 공통 선언에서 확인했다.
TextList는 [TextList](../../apps/web/src/components/form/TextList.tsx)의 bg-neutral-50 사용도 대조했다.
보조 버튼은 [ui/Button](../../apps/web/src/components/ui/Button.tsx)의 secondary이고, [form/Action](../../apps/web/src/components/form/Action.tsx)의 취소·저장하기를 위계 비교에 사용했다.
버튼 배경·기존 호버 배경·disabled 투명도는 유지한다. 비활성 Text의 neutral-400도 그대로 둔다.
입력 문구는 기존 공지 제목의 ‘제목을 입력하세요.’를 사용했으며, 문구 방향 DS-005의 구현은 이 비교에 포함하지 않았다.

견본은 React 컴포넌트의 시각 선언을 재현한 HTML이며 앱 전체 화면 캡처가 아니다.
직접 입력, Tab 이동, 보조 버튼 호버를 확인할 수 있고 초점의 고정 견본은 실제 초점과 따로 표시했다.
적용 범위는 공용 Text·TextArea·Button secondary다. 실제 페이지의 배경·초점을 대조했고 비활성 처리는 기존 클래스를 유지했다.
전역 neutral 토큰 값을 바꾸거나 모든 neutral-400을 치환하지 않는다. ui와 form의 독립 구현은 유지한다.

검색창 두 종류, 다른 입력·팝업·페이지별 보조 정보, 링크·오류·어두운 배경의 색은 아직 제안하지 않았다.
현재 입력 테두리의 대비와 전체 접근성 충족을 이 세 변경만으로 해결했다고 표시하지 않는다.
SunEditor·CSP·Sonner나 저장·검증 등의 기능 로직은 수정 대상이 아니다.

견본은 Playwright 1.57.0 Linux Chromium의 1280·390px에서 가로 넘침 없이 표시되는지 확인했다.
Tab으로 실제 입력칸에 이동했을 때의 초점 색·두께, 입력 가능 여부, 보조 버튼 호버와 초점 전후 크기 유지도 확인했다.
이 결과는 비교 문서 자체의 확인이다. 실제 앱 적용 확인은 아래와 구분한다.

## DS-008 실제 앱 적용 확인

새 프론트 프로덕션 빌드와 기존 로컬 API 이미지, Playwright 1.57.0 Linux Chromium에서 확인했다.

## DS-009 전체 색 구성과 다음 비교

사용자는 색의 전체 구성·선택 기준이 아직 정해졌는지 질문했고, 이후 작업에서도 확정 DS를 중간마다 보여달라고 요청했다.

## DS-012 입력 초점 외곽선 철회

사용자는 필수 형태가 아니라면 지난번 외곽선도 빼 달라고 요청했다.
Text·TextArea에 DS-008에서 추가한 초점 외곽선만 제거했고 기존 기본 테두리·캐럿·입력 예시 색은 유지했다.
C-Q6 검색 외곽선은 미적용 상태로 철회했다. 오류 red-600의 사용 기준은 이후 DS-013으로 확정했다.

## DS-013 오류 글자 유지

흰색·neutral-50의 오류 문장에 기존 red-600을 유지한다. [근거·범위](STATE-COLORS.md).
기존 앱 선언과 일치해 색 변경은 없으며 오류 검증 로직은 건드리지 않는다.
[주요 실행 비교](action-colors.html)는 DS-014로 확정했다. 기본 #404040 / 호버 #737373 / 흰 글자를 추가·예약 11곳에 적용했다. 새 빌드의 대표 4장면이 승인안과 일치했다. [근거·범위](ACTION-COLORS.md). 입력 경계와 컴포넌트별 상태는 형태와 함께 4단계에서 검토한다.

## 3-2 기반 색 검토 정리

DS-007~014로 주황, 기본 중립색 역할, 입력 예시·보조 버튼, 정보 링크, 오류 글자와 주요 실행의 값을 정했다.
승인한 첫 사용처는 적용·표본 확인했다. [누적 DS](index.html)의 각 항목이 적용 범위를 설명한다.
이는 전체 컴포넌트의 모든 색과 상태가 완료됐다는 뜻은 아니다.
입력 기본 경계, 선택·비활성·누름·처리 중·버튼 초점, 위험 행동·어두운 바탕은 4단계에서 형태와 함께 결정한다.
본문 작성자 스타일과 제외한 서드파티의 색도 일괄 치환하지 않는다. 주황/흰 글씨 대비 한계는 DS-007대로 남긴다.
