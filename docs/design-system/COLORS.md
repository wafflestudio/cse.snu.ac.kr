# 색 역할 — 주황과 작은 글자의 첫 비교

[현재 위치](PLAN.md) · [비교 견본](colors.html) · [기존 색 조사](ROLE-AUDIT.md)

3-2의 첫 질문 C-Q1이다. **제안 단계이며 앱 색상은 변경하지 않았다.**
전체 팔레트·상태를 한 번에 확정하지 않고, 보존하기로 한 주황과 작은 글자의 조합부터 정한다.

## 관찰과 근거

- [Tag](../../apps/web/src/components/ui/Tag.tsx)의 13px 흰 글자/주황 면, 주황 글자/흰 면은 각각 2.88:1이다.
  테두리 태그의 호버는 흰 글자/주황 면으로 전환한다.
- [SelectionList](../../apps/web/src/components/feature/selection/SelectionList.tsx)의 선택된 글자는
  #fafafa/주황 면으로 2.76:1이다. 크기는 모바일 11px, sm 13px, lg 14px다.
- [CornerFoldedRectangle](../../apps/web/src/components/ui/CornerFoldedRectangle/style.module.css)의
  주황 면과 접힌 모서리, [app.css](../../apps/web/src/app.css)의 주황 #ff6914를 기준으로 비교했다.
- 기존 대비 조사의 기준·수치는 [contrast.json](measurements/contrast.json), 새 후보 계산은
  [color-candidates.json](measurements/color-candidates.json)에 있다. 불투명 sRGB 조합이며 테두리·초점·전체 접근성을 판정한 값은 아니다.

## 두 안

| 역할 | 현재 | A · 추천 | B |
| --- | --- | --- | --- |
| 채운 태그의 면 / 글자 | #ff6914 / #ffffff, 2.88:1 | #ff6914 / #171717, 6.22:1 | #b54708 / #ffffff, 5.43:1 |
| 선택된 면 / 글자 | #ff6914 / #fafafa, 2.76:1 | #ff6914 / #171717, 6.22:1 | #b54708 / #ffffff, 5.43:1 |
| 흰 면 위 주황 글자 | #ff6914, 2.88:1 | #b54708, 5.43:1 | #b54708, 5.43:1 |
| 장식 주황 | #ff6914 | 유지 | 유지 |

A는 선명한 주황 면을 유지하면서 글자를 짙게 한다. B는 흰 글자를 유지하는 대신 글자가 있는 주황 면을 어둡게 한다.
작은 주황 글자는 두 안 모두 더 짙은 주황을 쓴다. A가 DS-001의 주황 면 보존에 더 가깝다고 판단해 추천한다.
새 #b54708은 이번 견본의 후보이며 확정 토큰이 아니다. 기존 main-orange-dark #e65817나 이전 브랜치를 정답으로 가져오지 않았다.

## 견본의 성격과 적용 경계

- colors.html은 소스 기반 HTML 견본이다. 실제 앱 스크린샷이나 React 컴포넌트 통합 검증으로 표시하지 않는다.
  태그 높이·패딩·13px/500, 선택 항목 40px·반응형 글자 크기를 사용했고, 접힌 모서리 CSS는 실제 파일을 읽는다.
  카드 폭과 주변 설명은 검토용 배치다. 선택 목록 전체의 그리드·주변 페이지는 재현하지 않았다.
- 비교 대상은 밝은 바탕의 Tag와 SelectionList에 있는 주황 텍스트/면 조합이다.
  주황을 전역 치환하거나 CornerFoldedRectangle의 다른 사용처를 자동으로 바꾸지 않는다.
- DS-004에 따라 저장·게시·예약 등 주요 실행은 짙은 중립색 기본이다. 이 질문에 주황 주요 버튼을 다시 승인받는 의미는 없다.
- 테두리 태그 기본/호버를 함께 보여준다. 채운 태그의 호버·삭제 아이콘·비활성 등 전체 상태는 선택 후 적용할 때 같은 원칙으로 대조한다.
  키보드 초점과 선택 표시의 비색상 단서, 보조 글자·입력 예시·링크·위험 행동·어두운 배경은 3-2의 후속 검토다.
- SunEditor 내부·CSP·에디터 서식 차이와 Sonner는 제외한다. 발견한 기능 버그는 메모만 남긴다.

견본은 Linux Chromium에서 1280·768·390px 렌더, 페이지 가로 넘침 없음, 태그 호버 색을 확인했다. 앱 통합 검증은 아니다.

## 이번 질문

**C-Q1: A처럼 기존의 밝은 주황 면을 유지하고, 그 위 글자에는 짙은 중립색을 사용하는 방향으로 갈까?**
흰 바탕의 작은 주황 글자는 #b54708처럼 더 짙게 나눈다. 흰 글자를 유지하는 인상이 더 중요하다면 B가 대안이다.
선택 후 해당 사용처에 적용하고 화면을 확인한다. 이어서 남은 색·초점 조합을 비교한다.
