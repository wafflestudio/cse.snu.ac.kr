## 소수점이 있는 코드를 어떻게 구분하는가

아래 px 환산은 기본 `1rem = 16px` 기준이다. rem 값 자체를 정수로 반올림하면 크기가 달라진다. 소수점 유무와 하드코딩 여부도 서로 다르다.

| 분류 | 실제 예 | 판단과 처리 경계 |
| --- | --- | --- |
| 정수 px를 rem으로 쓴 정상 표현 | `.625rem` = 10px, `.3125rem` = 5px, `.0625rem` = 1px, `.875rem` = 14px | Button·Dropdown 등에 존재. 숫자가 복잡해 보인다는 이유로 제거하지 않음. 동일값의 기존 유틸리티로 연결할 수 있는지는 재사용 필요와 실제 스타일 동일성을 보고 정리 |
| 가까워 보이지만 다른 값 | [form/Dropdown](../../apps/web/src/components/form/Dropdown.tsx)과 [ui/Dropdown](../../apps/web/src/components/ui/Dropdown.tsx)의 트리거의 기존 `pl-[.625rem]`(현재 `pl-2.5`)와 옵션 `pl-[.62rem]` | 10px와 9.92px로 **동일값이 아님**. 메인 ImportantSection의 `gap-[0.62rem]`도 별도 맥락. 반올림 오류·의도 보정 여부 미확정이며 별도 합의 없이 통일하지 않음 |
| 그래픽 접합용 좌표·길이 | Nodes의 18.81px 사선 길이, 5.1px/2.3px/16.7px 이동 | 회전한 선과 원을 잇는 기하 표현. 일반 여백 스케일의 누락으로 단정하지 않으며 접합 결과를 근거로 판단 |
| 효과의 정밀값 | [NewsCard](../../apps/web/src/routes/$locale/-components/news/NewsCard.tsx)의 31.9px 흐림 | 32px로 바꾸면 값이 달라짐. 단일 카드 효과를 위한 현재값으로 기록하고 통합할 근거가 생길 때 비교. 새 공통 그림자 단계로 확정하지 않음 |
| 상태·경계 조건의 소수점 | `useResponsive`의 기존 `639.98px`, 오류 색의 OKLCH 성분, 그림자 알파값 | 공간 정렬과 다른 역할. 일괄 숫자 반올림 대상에 넣지 않음 |

## 4단계 첫 동일값 정리

Button md의 `.875rem/.3125rem`은 `px-3.5/py-1.25`, 두 Dropdown 트리거의 `.3125rem/.625rem/.3125rem`은 `py-1.25/pl-2.5/pr-1.25`로 연결했다. 기존 spacing=.25rem을 사용하는 동일값 치환이다. 실제 폼 드롭다운의 계산 패딩5/10/5px를 확인했다. 옵션의 `.62rem`은9.92px로 다른 값이므로 유지했다. px를 rem으로 바꾸거나 반경1px를2px로 바꾸는 치환은 같은 값 정리로 취급하지 않는다.

파일 삭제 원의 직접값#a3a3a3은 DS-032 승인에 따라 currentColor와 기존 neutral-500/700을 참조하도록 변경했다. 이는 같은 값 치환이 아니라 승인된 기본/호버 색 변경이다. 파일명의 원문·행 크기와 SVG 흰 X는 유지한다.

DS-033은 ImageModal의 두 하단 버튼만 기존 focus-ring에 안쪽 offset:-4px를 적용한다. 전역 초점 위치는 그대로다. DS-034 닫기 색은 기존 neutral-600/100/200을 사용한다. 목록·태그제안의 DS-020과 CourseEditor4개 필수필드의 DS-027 연결을 추가했으며 남은 사진·복합상태와 전체 회귀는 구분한다.

DS-035 빈 검색 결과는 기존 neutral-500을 재사용한다. 새 색 토큰이나 문구·배치 변경은 없다. 미완료 초점 작업은 사용자 요청으로 마지막 단계로 보류했다.

DS-036은 기존 버튼 스타일·비활성40%를 유지하고 제출 중 문구만 교체한다. 폭은 기본 문구를 기준으로 확보하며 새로운 고정 크기 토큰을 만들지 않았다. `.styled-scrollbar`의 #d4d4d4 두 선언과 달력의 rgb(212 212 212)/white/#e65817을 기존 neutral-300/white/main-orange-dark 참조로 연결했다. 달력 경계·바탕·강조색의 계산값이 그대로임을 실제 예약 날짜창에서 확인했다.

DS-037 primary 호버는 기존 main-orange-dark를 참조하며 기본 main-orange/white는 유지한다. 확인창·교과목의 DS-005 문구 연결은 새 색·크기 토큰을 추가하지 않는다. 작은 확인창 RC-Q2는 미확정 제안이다.
