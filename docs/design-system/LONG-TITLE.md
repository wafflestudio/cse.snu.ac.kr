# LT-Q1 — 긴 페이지 제목은 크기를 유지하고 줄바꿈할까?

[실제 화면 비교](long-title.html) · [현재 DS](index.html) · [통합 검증](INTEGRATION.md)

## 현재 문제 → 제안 이유

5단계 전체 읽기 검증에서 10-10 프로젝트 참가자 페이지의 기존 가로 넘침을 확인했다. 한영320/390px에서 문서 폭이412px이다. 본문보다 긴 `Participants(Professors)` 제목과 제목 오른쪽 장식용100px 여백을 합친 최소 폭이 화면보다 크다. 이번 DS 변경 전 기준 이미지에도 있는 문제다.

공개 화면은320px까지 지원하기로 한 DS-028에 따라 실제 읽기 배치를 보완할 대상이다. 글자 크기 변경 없이 해결할 수 있어 DS-016의 기존 디자인 유지 기준에도 맞는다.

## LT-Q1 제안 — 기존24px와 그래픽 유지, 괄호 앞 줄바꿈

- 작은 화면에서 제목 상자가 본문 가로 영역을 넘지 않게 제한한다.
- `Participants`와 `(Professors)` 사이에 줄바꿈 가능 지점을 둔다. 문구·굵기·24px 글자 크기·색을 유지한다.
- 장식의 오른쪽 공간은 유지해 글자와 대각선이 겹치지 않게 한다. 충분히 넓으면 기존 한 줄이다.
- 확인한320/390px에서는 두 줄이 되어 제목 영역 높이가약29px 늘어난다.1280px는 원본과 같은 이미지다.
- 다른 페이지 제목을 일괄 두 줄로 만들거나 글자 크기를 바꾸는 제안이 아니다. 적용 시 공용 제목 사용처의 기존 배치도 함께 확인한다.

**아직 미적용이다.** 실제 앱을 연 뒤 브라우저 DOM에서만 비교 스타일·줄바꿈 지점을 적용했다. 한영320/390/1280px에서 현재/제안12개 장면을 확인했다. [측정](long-title-review/measurements.json).

## 같은 묶음에서 확인했지만 변경하지 않는 것

개인정보 표는 정지 캡처에서 오른쪽 열이 안 보여 별도로 확인했다. 기존 CSS가 표 영역만 가로 스크롤하도록 되어 있고,320px에서는416px,390px에서는346px만큼 실제 가로 휠 이동해 마지막 ‘보유·이용기간’ 열을 읽을 수 있었다. 내용 접근 불가로 판단하지 않으며 기존 표/명시된15·17·19px 글자 크기와 문구를 유지한다. 에디터 내부나 공유 본문 스타일은 추가 수정하지 않았다.

## 결정할 사항

LT-Q1: 넘치는 긴 페이지 제목을 **기존 크기로 유지하고 의미 단위로 줄바꿈**하는 제안을 적용할까? 추천은 적용이다. 변경 이유는 미관 선호가 아니라 공개 최소 폭에서의 가로 넘침이다.
