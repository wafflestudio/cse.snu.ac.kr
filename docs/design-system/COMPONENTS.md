# 컴포넌트·패턴 적용 현황

[누적 DS](index.html) · [계획](PLAN.md) · [기반값과 코드 연결](TOKEN-COVERAGE.md)

4단계는 공용 ui/form뿐 아니라 반복 패턴과 페이지 전용 컴포넌트를 포함한다. 기존값을 승인한 역할에 연결하고, 필요한 상태를 확인한다. 전체 컴포넌트의 재디자인이나 모든 숫자의 전역 토큰화가 목표는 아니다.

**현재: 4단계의 비접근성 형태·상태·문구 정리를 마치고, 5단계 일반 시각 통합 검증을 진행한다.** 전체 읽기 화면 회귀 결과는 아직 확정하지 않았다. 남은 접근성 적용·검증은 사용자 요청대로 마지막에 재개한다.

## 적용 범위와 검증 경계

- 입력: 기본·필수·오류·비활성. DS-012대로 텍스트 입력에 추가 초점 외곽선을 넣지 않는다.
- 선택: ui/form의 별도 구현, 체크·라디오·드롭다운의 키보드·선택·펼침·비활성.
- 파일·이미지: 선택·목록·삭제·이름. 주요 기능 문제는 별도 기록한다.
- 탐색·정보: 페이지 이동·목록·카드·페이지 전용 패턴의 관련 상태.
- 확인·피드백: 모달·오류·처리 중. Sonner 내부는 제외한다.

기존 서체·색·크기·간격의 유효한 차이는 역할과 예외로 유지한다. `.62/.625rem` 같은 다른 값의 통합은 실제 근거와 비교 후 합의하고, 동일값의 유틸리티 연결은 픽셀 변화 없이 진행한다. 이전 검증 자료를 재사용하며 새 변경·미확인 경계에 집중한다.

## 추가 연결·동일값 정리

- DS-020을 form/Checkbox·Radio·Dropdown·DatePicker, File·Image의 선택/삭제에 연결했다. 텍스트 입력의 캐럿 표시는 그대로다. [8개 초점 표본](form-controls-implementation/measurements.json).
- 파일·이미지의 hidden 입력을 sr-only로 바꾸어 네이티브 Tab/Space 선택 경로를 확보했다. 파일 삭제 이름은 파일명을 포함한다. 공지 작성의 키보드 파일 선택·삭제 영구 E2E가 통과했다. 업로드·저장 로직은 변경하지 않았다.
- Button md의 가로14px/세로5px를 px-3.5/py-1.25로, ui/form Dropdown의 위아래5px·왼쪽10px·오른쪽5px를 기존 간격 유틸리티로 연결했다. 같은 rem값이며 크기를 바꾸지 않았다. `.62rem` 옵션·특수 모서리·그림자 값은 유지한다.
- form Dropdown의 닫힌 옵션 Tab 이동은 기존 기능 문제 Q-15로 기록했다. 초점 모양 연결을 키보드 동작 전체 완료로 확대하지 않는다.
- DS-031 B 한 줄 파일명과 DS-032 삭제 기본500/호버700을 [적용·대표 검증](file-controls.html)했다. 1200/1280px의 긴/짧은 파일명과 키보드 삭제를 확인했다.

## 탐색·확인 상태 연결

- DS-020을 Pagination 번호/활성 화살표, 공지 제목 링크, PostFooter 앞뒤 글, CategoryGrid 카드, ui/Dropdown 트리거, ImageModal 체크 라벨에 연결했다. 기본색·크기·선택·호버·탐색 로직은 유지했다.
- [대표 검증](navigation-focus-implementation/measurements.json): 페이지2·공지 Enter 이동, 앞뒤 글 초점, 확인창 취소/Escape, 어두운 카테고리 두 사용처, 졸업생 진로 드롭다운 키보드, 이미지 체크 Space/해제. CategoryGrid light는 사용처가 없어 소스 연결만 완료. 전체 제목·페이지·언어의 검증을 뜻하지 않는다.
- [DS-033·034 적용](clipped-focus.html): 이미지 안내창 하단 두 버튼의 안쪽 초점과 닫기 색을 적용·대표 검증했다. 메인 카드의 단순 안쪽선은 상단 이미지에 가리므로 후속 배치·대비 비교가 필요하다.
- SelectionList·검색 결과·새 소식/세미나·인물 이름/정보 링크의 DS-020을 연결했다. 대표 선택 변경·320px 검색 결과·목록 초점을 확인했다. 새 소식 사진 링크는 소스 연결했지만 이번 로컬 표본에 사진 링크가 없어 렌더 미검증. PeopleGrid 사진의 초점은 별도 확인이 남는다.

## 오류 표시와 유지하는 상태

- CourseEditor의 필수4개에 DS-027을 추가 연결했다. 오류문장은 DS-005대로 한/영 교과목명·설명을 구분하고 UI 언어에 맞춰 입력을 요청한다. 한영 표시·재입력 해제·180/308px 이름 입력 폭을 확인했다. 실제 저장 요청은 없었다. NoticeEditor 태그 제안에도 DS-020을 연결했고 요청은 실행하지 않았다. [실제 표본](list-error-implementation/measurements.json).
- 입력 경계neutral-300·예시500·필수 주황 별표는 기존 맥락으로 유지한다. 버튼 비활성40%·드롭다운30%·입력 비활성 글자400은 역할별 기존 예외다. 값 차이만으로 통일하지 않는다. Radio에 없는 disabled API나 처리 중 상태를 새로 만들지 않는다.
- DS-036으로 Form.Action·예약의 기존 isSubmitting 안내를 버튼 안에 연결했다. 공지·뉴스는 생성 게시/편집 저장을 구분한다. Form.Action27개 모듈의 handleSubmit 연결을 소스로 확인했고 공지 작성·편집/예약 한영6장면을 실제 요청으로 검증했다. 폼 확인창 행동·대상과 교과목 저장은 DS-005로 연결했다. 예약 용어도 DS-038로 버튼·확인·완료에 연결했다. 없는 재시도 버튼이나 오류 처리 흐름을 문구 작업으로 추가하지 않는다.
- [DS-035 적용](card-empty.html): 빈 검색 결과는 neutral-500 색만 변경하고 한영 문구를 유지했다.
- 사용자 요청으로 메인 카드·인물 사진 등 미완료 접근성 작업은 나머지 DS 완료 뒤로 보류했다. 이번 시험의 초점 변경은 앱에서 되돌렸다. [처리 중 표시](pending-feedback.html)는 적용했다. [primary 호버](primary-hover.html)와 폼 확인창도 적용했다. 예약 용어·작은 확인창도 DS-038·039로 적용했다. 다음은 5단계 일반 시각 통합 검증이다.

스크롤바와 달력의 동일 색값을 neutral-300/white/main-orange-dark 토큰에 연결했다. 달력 반경·크기·선택 바탕과 `.62/.625rem` 등의 유효한 차이는 유지한다. 형태·그림자의 새 변경 근거는 발견하지 못했으며 전수 시각 검증 완료를 뜻하지 않는다.

## 4단계 마감 분류

- 적용 완료: DS-037 primary 호버, DS-005 확인창 행동·대상과 교과목 저장 행동명. [실제 견본](confirmation-copy.html).
- 유지 확정: 역할별 모달 크기, 선택과 문서 이동의 표현 차이, 비활성 Button/uiCheckbox40%·Dropdown30%·Tag60%·입력 글자400. 같은 값의 재사용과 다른 값의 통합은 구분한다.
- 적용 완료: [DS-038 예약 취소 용어·DS-039 작은 확인창 배치](reservation-copy.html). 버튼·확인·완료를 취소로 맞추고 반대 행동은 예약 유지로 구분했다. 공용 AlertDialog는 640px 미만에서 90vw/최대512px, 버튼 글자 줄바꿈 금지·버튼 단위 줄바꿈을 적용했다. 640px 이상 기존 내용 기반 폭은 유지하며 줄바꿈에 따라 높이는 달라질 수 있다. [예약 20개 배치·한영 실제 취소 완료](reservation-copy-implementation/measurements.json)와 [다른 확인창 4개](reservation-copy-implementation/other-alert-measurements.json)를 확인했다. API·권한·단건/반복 범위는 유지했다.
- 일반 시각 검증 진행: 대표 검증 밖의 읽기 화면·반응형 조합을 5단계에서 대조한다. read/read-mobile 회귀는 실행 중이며 전체 통과나 기준 이미지 갱신 완료로 표시하지 않는다.
- 마지막 접근성: 메인 카드·인물 사진과 남은 탐색/초점/속성 검증. DS 나머지 완료 뒤 재개한다.
- 범위 제외: SunEditor 내부·CSP·Sonner 내부·기능 버그. Q목록으로 관리한다.

## DS-040 — 긴 페이지 제목

괄호 앞 줄바꿈 지점이 있는 제목은 작은 화면에서 상자 폭을 제한하고 의미 단위로 줄바꿈한다. 모바일24px·데스크톱32px와 장식용100px 공간을 유지한다. 참가자 한영3폭6장 승인안 일치·다른 제목24장 기존 동일 확인. [실제 적용](long-title.html). 긴 경로 표시는 이후 DS-041로 단계별 줄바꿈·왼쪽 텍스트 정렬을 적용했다. [실제 적용](breadcrumb.html).

## DS-041 — 경로 줄바꿈의 왼쪽 정렬

구분 화살표와 다음 이름을 한 단위로 줄바꿈하고, 긴 항목의 텍스트는 왼쪽에 정렬한다. 작은 화면에서는 제목 영역을 기존 좌우20px 안으로 제한한다. 경로 줄 간격4px·그래픽 최소100px 공간을 사용하며 기존 글자 크기·문구·링크 동작을 유지한다. 한영48상태와 대표6이미지·경로 링크 이동을 확인했다. 접근성 후속은 미재개다.
