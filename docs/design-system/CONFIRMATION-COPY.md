# 확인창의 행동·대상 — DS-005 후속 적용

[실제 견본](confirmation-copy.html) · [계획](PLAN.md) · [예약 용어 검토](reservation-copy.html)

DS-005의 기존 합의를 실제 동작에 연결했다. 새로운 디자인 방향 결정이 아니다.

| 문맥 | 적용 문구 | 실제 결과 |
| --- | --- | --- |
| 변경한 편집 폼에서 취소 | 저장하지 않은 변경사항을 버릴까요? / 계속 편집 · 나가기 | 계속 편집은 입력 유지, 나가기는 기존 onCancel 실행 |
| 이미지 안내 관리에서 취소 | 같은 설명 / 계속 편집 · 되돌리기 | 화면 이동 없이 기존 초기값으로 복원 |
| 폼의 삭제 | 이 공지사항을 삭제할까요? 등 대상 명시 / 취소 · 삭제 | 기존 삭제 콜백 실행 |
| 교과목 편집 | 변경사항 저장 / Save changes | 기존 저장 콜백 실행 |

삭제 대상은 공지사항·새 소식·세미나·교수 정보·행정직원 정보·연구실·이미지 안내다. 교수/역대 교수는 같은 Editor를 쓴다. 삭제 콜백이 없는 폼에는 삭제 확인창을 새로 만들지 않았다. Form.Action의 26개 모듈은 이탈, 이미지 관리1개는 초기화임을 소스로 대조했다.

AlertDialog에는 반대 행동 문구를 전달할 cancelText를 추가하고 기본 취소/확인만 언어별로 연결했다. 명시 전달 문구와 초점·열기·닫기·콜백 로직은 유지한다. 공용 Form.Action에는 초기화 예외와 대상별 설명만 전달한다.

실제 프로덕션 빌드1200px의 한영 공지에서 계속 편집·삭제 취소·나가기를 확인했다. 한국어 직원 삭제 대상과 이미지 관리 초기화도 확인했다. 교과목 한영 저장 문구는 표시와 취소만 확인하며 실저장은 기존 CRUD 테스트로 확인한다. 모든 폼의 모든 문구·모바일 편집을 검증한 것은 아니다. [측정](confirmation-copy-implementation/measurements.json).

예약의 삭제→취소는 별도 문구 제안이다. 현재 앱에서는 아직 삭제라고 표시한다. 접근성 후속은 나머지 DS 완료 뒤에 진행한다.
