# 긴 선택 항목의 배치 — DS-024 적용

[누적 DS](index.html) · [실제 비교](filter-layout.html) · [현재 계획](PLAN.md)

## 현재 상태

DS-023 B안은 승인·적용했다. 탐색 1200px / 교과목·예약 1024px 기준을 분리했고 승인 12장면이 일치했다.
기존 390·1280px의 9유형 × 2언어 전체 페이지 이미지 36장도 직전 버전과 일치했다.
**L-Q3의 메인 필터 줄바꿈·공지 태그 A안을 승인받아 DS-024로 앱에 적용했다.**
데스크톱 편집·관리 24개 상태도 이어서 실측했다. 3-6 모양·크기는 아직 착수하지 않았다.

## 문제와 변경 이유

### 메인 공지 필터

영어 390px에서 네 선택 항목을 한 줄로 고정해 문서가 420px까지 늘어난다.
직전 버전에서도 동일했다. 좁은 화면에서 끝 항목이 화면 밖에 놓인다.
**확정·적용:** 항목 모양·글자·색·순서·간격을 유지하고, 들어가지 않는 항목만 다음 줄로 넘긴다.
390px 영어에서 Graduate가 둘째 줄로 내려가 문서 폭이 390px로 맞고, 공지 영역 높이가 늘어난다.
한국어 390px와 넓은 화면처럼 한 줄에 들어가는 경우는 유지한다.
색·라디오 동작·주황 대비는 이번 판단 대상이 아니다.

### 공지 태그

현재 태그의 열 최소 폭은 160px지만, 영어의 가장 긴 항목은 약 237px다.
1024px에서는 5열로 배치되어 오른쪽으로 넘치고 일부 항목도 겹친다.
768·1280px에서는 페이지 전체가 넘치지 않아도 같은 줄의 항목끼리 겹친다.
따라서 페이지의 scrollWidth만 맞추는 것으로는 충분하지 않다.

| 안 | 배치 | 유지·변경 | 대가 |
| --- | --- | --- | --- |
| **A — 열 정렬 유지 (승인·적용)** | 영어에서 가장 긴 항목이 들어가는 최소 240px 열로 자동 배치 | 기존 같은 폭의 열·행 우선 순서·간격 유지. 한국어 기존 열 유지 | 1024px에서 5열→3열, 필터 영역 높이 증가 |
| B — 항목 길이에 맞춰 배치 | 항목마다 필요한 폭을 쓰고 남는 공간이 부족하면 다음 줄로 | 이름·순서·간격 유지. 같은 폭의 열 정렬을 없앰 | 더 조밀하지만 줄마다 시작 위치가 달라짐. 한국어 배열도 달라짐 |

**A 선택 이유:** 기존 열 정렬을 보존하면서 겹치는 원인인 열 폭만 맞춘다(DS-016).
240px는 임의로 키운 크기가 아니라 현재 영어 최장 항목 약 237px를 담는 비교값이다.
모든 선택 컨트롤의 새 공통 폭을 240px로 정하자는 제안은 아니다.
B도 읽기 가능한 대안이며 같은 높이에 더 많은 항목이 들어간다. 대신 기존 정렬 방식이 달라진다.
글자를 줄이거나 이름을 생략하는 안은 포함하지 않았다.

## 승인 전 비교 기록

새 DS-023 프로덕션 빌드 + 기존 로컬 API + Playwright 1.57.0 Linux Chromium에서 DOM 스타일만 임시 조정했다.
메인은 한·영 390/768/1280px의 기존/줄바꿈, 공지는 한·영 390/768/1024/1280px의 기존/A/B를 비교했다.
[36개 비교 상태의 실측 기록](filter-layout-comparison/measurements.json). 제안 표본에서 문서 가로 넘침·같은 줄 항목 경계 겹침이 없었다. 메인 줄바꿈은 영어 390px만 달라지고 나머지 5개 언어/폭 이미지는 현재와 같았다. 이는 견본 측정이며 앱 적용 검증은 아니다.
실제 화면을 같은 뷰포트로 캡처했고, 메인은 공지 영역으로 스크롤했다. 문서에서는 축소해 보여주며 원본을 열 수 있다.

## 실제 적용·검증

새 프로덕션 빌드의 메인 6장·공지 8장, **총 14장 이미지가 승인 A 견본과 바이트까지 일치**했다.
메인·공지·뉴스·통합검색을 한·영 360/390/639/640/768/1024/1199/1200/1280px에서 총 72개 상태로 실측했다.
메인·공지는 이 표본에서 페이지 가로 넘침·같은 줄 항목 겹침이 없었다.
한국어 공지와 뉴스·통합검색의 기존 열 정의는 변경하지 않았다.

메인 라디오의 방향키 선택·복귀, 공지 체크박스의 Space 선택·해제와 URL/결과 연결,
STAFF 편집 모드의 태그 비활성·완료 후 복귀를 확인했다. 서버 저장·삭제는 실행하지 않았다.
앱 기능 로직은 변경하지 않았다.
[실제 적용 기록](filter-layout-implementation/measurements.json).

공유 사용처 확인 중 **영어 통합검색**의 `Research & Edu`가 옆 항목과 겹치는 기존 문제를 확인했다.
이 그룹은 80px 열을 사용하며 가장 긴 항목은 약 133px다. 공지의 240px를 모든 그룹에 적용하지 않고 별도 사용처로 비교한다.
따라서 공용 태그 전체의 배치가 완료됐다고 보지 않는다. 뉴스 표본은 이번 범위에서 겹침이 없었다.

검토 문서는 1280·390px에서 가로 넘침·내부 링크·모든 언어/폭 이미지 전환을 확인했다.
전체 회귀·큰 글자·임의의 긴 언어 데이터는 5단계 검증 범위에 남는다. 편집기·Sonner는 제외한다.
