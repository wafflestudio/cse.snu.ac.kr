# 공통 초점 표시 — DS-020

[누적 DS](index.html) · [실제 비교·직접 조작](focus.html) · [진행 계획](PLAN.md)

사용자는 I-Q3를 승인하면서 “초점시에 어떻게 표시할지는 통일할 필요가 없을까?”라고 요청했다.
개별 아이콘의 숨김 문제를 해결하는 것과 함께, 4단계에 예정했던 공통 초점 표시의 기준을 먼저 검토한다.
**F-Q1은 승인됐다. 공통 스타일과 대표 네 사용처에 적용했으며 나머지 컴포넌트는 4단계에서 이어간다.** 카드 화살표의 표시 조건은 DS-019, 둘레 모양은 DS-020이다.

## 현재 문제 → 이유 → 효과

대부분의 버튼·링크는 브라우저 기본 `auto` 초점 표시다. 교수 정렬은 짙은 회색 2px/간격 2px이고, 메인 공지 분류는 같은 크기에 주황색이다.
일부 ImageModal 버튼은 `focus:outline-none`이며, 입력은 DS-012에 따라 추가 외곽선을 없애고 캐럿을 유지한다.
브라우저 기본 표시 자체가 잘못된 것은 아니다. **같은 역할의 초점 표현을 일관되게 정하고 누락을 확인할 기준을 만들기 위한 제안**이다.

초점은 지금 키보드로 조작할 대상을, 선택은 현재 선택된 값을, 호버는 포인터 위치를 보여준다.
배경색 변경만으로 초점을 표시하면 선택·호버와 혼동하기 쉬워, 버튼·링크의 초점은 둘레 표시로 구분하는 것을 추천한다.
입력은 편집 위치를 알려주는 캐럿이라는 기존 표현을 유지한다. 입력에 추가 외곽선을 다시 넣는 제안이 아니다.

## 확정 규칙

| 대상·상태 | 확정값 | 이유·범위 |
| --- | --- | --- |
| 버튼·아이콘 버튼·링크 | `:focus-visible`에 2px 실선 / 바깥 간격 2px | 교수 정렬에서 쓰는 기존 두께·간격을 출발점으로 사용. 버튼 배경·글자·그림은 유지 |
| 밝은 면 위의 초점 | neutral-700 **#404040** | 흰색·옅은 회색에서 식별. 글자 색이나 브랜드 주황에 종속시키지 않음 |
| 어두운 면 위의 초점 | **#ffffff** | 어두운 면에서 동일한 두께·간격으로 식별 |
| 밝고 어두운 면에 걸치는 요소 | 짙은 2px 바깥선 + 안쪽 흰 2px 보조선 | 헤더 검색은 버튼 높이가 바와 같아 바깥선이 어두운 면까지 걸친다. 단색은 일부가 묻히므로 두 색 사용 |
| 라디오·체크 등 복합 선택 | 초점 대상에 대응하는 보이는 컨트롤/라벨에 같은 둘레 표시 | 숨겨진 input 자체에만 그리지 않음. 그룹·선택·포커스를 혼동하지 않기 |
| 텍스트 입력·textarea·검색 입력 | 기존 캐럿·텍스트 선택 유지, 추가 외곽선 없음 | DS-012 유지. 키보드 초점·입력 위치가 실제로 보이는지 확인 |
| 호버에서만 드러나는 조작 | 키보드 초점으로도 드러내고 현재 대상에는 공통 초점 표시 | DS-019의 표시 조건과 공통 초점 모양을 연결 |

색은 **요소의 글자색이 아니라 초점 선이 실제로 놓이는 배경**을 기준으로 고른다.
주황 버튼이라도 바깥 면이 흰색이면 #404040을 쓴다. 브랜드 주황 값과 선택 상태의 채움은 바꾸지 않는다.
2px 간격은 표시를 버튼과 분리하기 위한 값이다. 밝음/어두움의 차이는 같은 목적을 달성하기 위한 배경별 규칙이며 임의의 예외색을 추가하는 것이 아니다.
흰 보조선은 경계·복잡한 배경에서만 검토한다. 사진·투명 면은 사용처 확인 없이 자동으로 적합하다고 보지 않는다.

## 접근성의 요구와 디자인 선택을 구분

[WCAG 2.4.7(AA)](https://www.w3.org/WAI/WCAG22/Understanding/focus-visible.html)은 초점 위치가 보이는 방식을 요구하지만 특정 선 두께나 모든 요소의 같은 모양을 요구하지 않는다. 입력의 캐럿도 예로 든다.
[1.4.11(AA)](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)은 작성자가 정한 초점 표시를 인접 색과 구별할 수 있어야 함을 설명한다. 새 색을 정했다는 사실만으로 적합성이 보장되지는 않는다.
[2.4.13(AAA)](https://www.w3.org/WAI/WCAG22/Understanding/focus-appearance.html)은 2px 둘레에 해당하는 면적 등을 다루며 문자 그대로 2px 외곽선만 허용하는 규칙은 아니다.
이번 **2px 선·2px 간격은 DS의 확정값**이다. AA의 필수값이나 사이트 전체 AAA 적합성을 선언하는 것이 아니다.

## 실제 비교와 적용 경계

[대표 4장면](focus-system-comparison/measurements.json): 교과목 화살표, 어두운 헤더의 로그인, 밝고 어두운 면 경계의 검색 버튼, 교수 정렬.
실제 키보드 초점을 유지하면서 모양만 임시로 지정했다. 전후 대상의 위치·크기는 동일했다. 교수 정렬은 기존 규칙과 같다.
교과목 화살표의 바깥선은 인접 카드가 덮을 수 있어 초점 버튼의 표시 순서를 앞에 두는 조건도 비교에 포함했다. 둘레 CSS만 일괄 추가하면 안 되는 이유다.
현재 캡처는 한국어 1280px Chromium 표본이다. 다른 브라우저의 기본 초점 모양을 동일하게 단정하지 않는다.

공통 스타일은 `app.css`의 `focus-ring`, `focus-ring-inverse`, `focus-ring-boundary`로 정의한다.
사용처에서 `focus-visible:` 또는 보이는 라벨의 `has-[:focus-visible]:`로 연결한다. 헤더의 버튼·링크는 부모의 직접 자식 선택자로 한정했다. 공용 Button API는 확장하지 않았다.
첫 적용은 교과목 화살표, 헤더 상단 로그인·언어·관리 링크, 헤더 검색 실행, 교수 정렬 라벨이다. 나머지 컴포넌트는 4단계에서 연결한다.
`*:focus`로 전체를 덮거나 기존 초점을 먼저 제거하지 않는다. 해당 컴포넌트별로 적용한다.
외곽선 잘림·좁은 간격·줄바꿈 링크·라디오와 체크의 라벨·강제 색상 모드를 확인한다. box-shadow 보조선이 강제 색상 모드에서 사라질 수 있으므로 실제 outline과 시스템 색상을 확보하는 것이 후속 구현 조건이다.
SunEditor·Sonner는 계속 제외한다. ImageModal 등의 누락은 공통 기준 승인 후 해당 컴포넌트의 상태 검토로 연결한다.

## 결정과 적용

사용자가 “ㅇㅇ 진행하자”로 승인했다(DS-020). [실제 적용 기록](focus-system-implementation/measurements.json)에 대표 사용처의 모양·위치·강제 색상 모드 확인을 남긴다.
강제 색상 모드에서는 실제 outline에 시스템 `Highlight` 색을 쓴다. 교과목 화살표는 초점 시 표시 순서를 앞에 둬 인접 카드가 선을 덮지 않게 한다.
사진 배경·줄바꿈 링크·복합 선택·모달·모바일 사용처 전체의 완료를 뜻하지 않는다.

## 앱 적용 확인

새 프로덕션 빌드의 한국어 1280px에서 네 장면이 승인 견본과 바이트까지 일치했고, 대상 위치·크기도 같다. 라디오 방향키·초점 이탈과 검색 입력의 추가 외곽선 0px·입력 유지도 확인했다. 강제 색상 모드에서는 네 대상 모두 실제 2px outline이 남고 검색 보조 그림자가 없어져도 선이 유지됐다. 다른 브라우저·전체 컴포넌트 검증은 아니다.

## 검토 문서 확인

누적 DS·카드 적용 결과·공통 초점 비교를 1280·390px에서 확인했다. 가로 넘침과 내부 링크, 4장면 이미지 전환을 확인했다.
Tab 이동으로 밝은 면·어두운 면·경계의 선과 색, 선택 컨트롤 방향키 이동, 입력의 외곽선 0px·텍스트 입력을 확인했다. 이는 문서 견본 검증이며 앱 전체 적용 검증이 아니다.
