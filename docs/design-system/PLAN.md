## 목표와 범위

기존 사이트를 조사하고 사용자와 방향을 정해, 새로운 화면을 만들 때 일관되게 판단할 수 있는
디자인 시스템 v1을 만든다. 규칙은 실제 화면과 상태에서 검증하고 문서로 남긴다.

조사 대상은 공개 화면, 편집·관리 화면, 공용 컴포넌트, 페이지 전용 패턴, 본문 뷰어와
에디터의 연결부다. 한국어와 영어, 작은 화면과 큰 화면, 기본 상태와 상호작용 상태를 포함한다.
서드파티 내부와 작성자가 입력한 콘텐츠는 사이트가 관리하는 스타일과 구분해 범위를 명시한다.
공개 기능은 모바일·데스크톱을 지원하며, 행정실의 편집·관리는 데스크톱 중심으로 검증한다.
모바일 편집 전용 배치 최적화는 v1 필수 조건에서 제외한다. 공용 폼을 사용하는 일반 이용자의
예약 등은 모바일 범위에 남는다. 세부 경계는 DS-003을 따른다.

현재는 디자인 변경을 우선한다. 기능·주요 로직 버그는 메모로 남기고 별도 요청 없이 수정하지 않는다.
SunEditor 내부 동작·CSP·에디터의 서체/서식 차이와 Sonner 수정은 현재 범위에서 제외한다.
승인한 공유 본문 CSS의 기본 서체 연결은 유지하되 에디터 문제 해결을 완료 조건으로 삼지 않는다.

보존할 정체성과 개선할 부분은 첫 조사에서 함께 정한다. 토큰 개수 최소화, 모든 페이지의 전면
재디자인, 제품 기능·백엔드의 확장은 별도의 합의 없이 목표에 추가하지 않는다.

## 2–4. 함께 결정하고 적용하는 방법

각 검토 단위는 다음 순서를 따른다.

1. **질문:** 이번에 결정할 문제와 영향을 받는 사용처를 짧게 적는다.
2. **관찰:** 기존 화면의 공통점·차이·문제를 근거와 함께 보여준다.
3. **제안:** 추천안과 필요한 대안을 실제 화면 또는 비교 가능한 견본으로 제시한다.
4. **결정:** 사용자와 검토한 결과, 이유, 적용 범위와 예외를 남긴다.
5. **적용·검증:** 실제 사용처와 문서에 반영하고 화면·상태를 확인한다.

분석, 기준 화면 수집, 되돌릴 수 있는 비교안 제작은 진행한다. 사용자와 함께 검토할 디자인
선택을 에이전트가 기존 브랜치의 결론으로 대신하지 않는다. 합의된 범위의 구현과 검증은 반복
확인 없이 완료한다. 새로운 의사결정이 필요하면 구현 전에 구체적인 비교물을 준비한다.

기반 규칙에서는 값뿐 아니라 사용 기준을 정한다. 색은 배경과 상태의 조합, 타이포는 정보의 역할과
읽기 맥락, 아이콘은 그림과 조작 영역, 레이아웃은 콘텐츠와 전환 조건을 함께 다룬다.
이전의 특정 크기·폭·굵기·단계 수는 확정값이 아니다.

컴포넌트는 기본·호버·누름·초점·선택·비활성·오류·처리 중 등의 상태 중 해당하는 것을 확인한다.
일반 사용, 잘못된 사용, 예외를 구분하고, 공용화할 범위는 실제 요구에 따라 정한다.

## 진행 관리

- 중간 검토마다 질문에 앞서 확정된 DS 내용과 견본을 보여준다. `index.html`에 규칙을 누적하고 방향 확정·앱 적용·미확정을 구분한다.
- 현재 작업은 하나로 유지한다. 범위가 크면 다음에 판단 가능한 단위로 나눈다.
- 사용자 판단이나 답변이 필요한 질문이 생길 때까지 계획 안의 다음 작업을 이어간다. 중간 산출물 완료만으로 ‘계속’ 지시를 기다리지 않는다.
- 각 항목은 `미착수 → 조사됨 → 제안됨 → 결정됨 → 적용됨 → 검증됨`으로 추적한다.
- 문서 작성, 사용자 결정, 코드 반영, 화면 검증은 서로 다른 상태다.
- 작업 중 다른 문제가 나오면 아래 후속 목록에 넣는다. 현재 작업의 선행 조건일 때만 순서를 바꾼다.
- 끝난 결정을 다시 열 때는 새로운 근거와 영향을 기록한다.
- 매 작업 종료 시 상단 현황, 해당 항목의 상태, 다음 행동을 갱신한다. 대화 기록을 다시 읽어야만
  현재 위치를 알 수 있는 상태로 두지 않는다.
- 조사 결과는 필요할 때 `INVENTORY.md`, 결정은 `DECISIONS.md`로 분리한다. 진행 상태는 이 파일에만 둔다.

## 검증과 v1 완료 기준

검증 환경과 절차는 루트·프론트·E2E의 `CLAUDE.md`를 따른다. 공식 시각 회귀는 기존 E2E 환경에서
실행한다. 탐색용 렌더링은 공식 검증과 구분해서 기록한다.

- 공개 기능의 대표 화면과 고유한 예외는 한국어·영어, 모바일·중간 폭·데스크톱을 확인한다.
- 행정실 편집·관리는 데스크톱에서 입력·오류·저장 흐름을 확인한다. 최소 지원 폭은 레이아웃 검토에서 정한다.
- 결정한 전환점의 직전·직후, 긴 텍스트, 키보드 초점, 관련 상태 전환을 확인한다.
- 데이터가 적거나 특정 상태에 접근하지 못했으면 검증 한계를 적는다.
- 변경한 영역에 필요한 타입·린트·동작·시각 검증을 수행한다. 값마다 구현을 복제하는 테스트는 만들지 않는다.
- 의도된 변경과 예상 밖의 회귀를 검토한 뒤 스크린샷 기준을 갱신한다.

v1은 핵심 영역의 규칙과 예외가 설명되고, 실제 사용처와 문서가 일치하며, 합의된 검증 범위에서
주요 읽기·탐색·조작 문제가 해결됐거나 사용자와 유지하기로 결정한 한계가 분리됐을 때 완료한다.
DS-007의 주황/흰 글씨 대비 미달은 알려진 한계로 남기며 전체 WCAG AA 충족을 선언하지 않는다. 남은 문제는 영향과 후속 작업이 명시되어야 한다.
모든 값을 토큰으로 만들거나 모든 예외를 없애는 것을 완료 조건으로 삼지 않는다.
