예약 입력칸이 창 안에 들어오도록

DS-026 · 적용 완료
현재 DS 전체확정·적용실제 비교이번 판단

먼저, 통합검색 적용 완료

DS-025: 영어 통합검색 태그는 최소 160px 열을 사용한다. 공지의 240px·뉴스·한국어 기존 열은 유지했다. 한·영 대표 6장면이 승인 견본과 일치했고 키보드 선택·해제·검색 결과 연결을 확인했다. 실제 적용 보기.

3-6에서는 기존 모서리·크기·그림자의 역할을 정리하고 이전 검증을 재사용한다. 먼저 이미 기록했던 모바일 예약창 넘침을 확인했다. 기존 기준·예외·남은 확인.

왜 오른쪽이 잘릴까?

390px 화면에서 모달 안쪽 공간은 295px인데 네 입력칸은 352px 고정이다. 사용 목적 칸은 맞지만 단체 이름·이메일·전화번호·지도교수는 오른쪽으로 넘친다.

제안은 기존 352px 폭에 창 안쪽 폭을 넘지 않는 제한을 추가하는 것이다. 좁은 창에서만 줄이고 데스크톱의 크기·배치를 유지한다. 글자·색·높이·간격·예약 동작은 그대로다.

실제 화면에서 비교

현재 · 352px 고정

원본 크기

실제 적용 · 창 안쪽 폭으로 제한

원본 크기

390px에서 입력 352→295px, 내부 스크롤 폭 380→351px로 맞는다. 한·영 데스크톱 1280px의 전후 이미지는 동일하다. 예약창 전용 입력 묶음의 폭 제한만 바꾼 비교다.

한·영 두 폭과 모바일 날짜 펼침, 총 10개 전후 상태를 확인했다. 승인 후 실제 앱에 적용했다. 모바일 내용 영역·데스크톱 이미지가 승인안과 일치한다. 전체 모바일 캡처의 경계 차이는 상세 기록에 구분했다. 예약 저장은 하지 않았다. 측정·이유·적용 경계와 한계.

결정 · DS-026

승인에 따라 네 입력칸은 기존 352px를 유지하되, 좁은 창에서는 안쪽 폭을 넘지 않도록 적용했다.

공용 모달·입력의 전체 상태는 기존 계획대로 4단계에서 이어간다. 최소 지원 폭·전체 예약 동작의 검증 완료를 뜻하지 않는다.
