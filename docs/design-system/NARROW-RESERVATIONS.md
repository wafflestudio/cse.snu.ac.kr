# 작은 화면과 예약 상태 — DS-028~030 적용

[실제 비교](reservation-boundary.html) · [현재 DS](index.html) · [계획](PLAN.md)

2026-09-24. DS-026·027 적용 후 새로 확인한 상태를 묶었다. 사용자 승인으로 **DS-028~030 확정·적용**했다. 아래는 변경 이유와 승인 전 비교 기록이다.

## DS-028 검증 범위

공개 화면·예약320 CSS px부터, 행정실 편집·관리1200 CSS px부터를 최소 검증 폭으로 확정했다. 전자는 DS-003 공개 모바일 지원, 후자는 사용자에게 모바일 편집 수요가 없었던 결정과 기존1200/1280/1440px 편집24상태 조사를 잇는다. 기존320px 소개/푸터와 이번 한·영 공지/검색·예약 표본을 근거로 시작하되, 해당 폭 이상의 전체 사이트 통과를 선언하지 않는다. 4·5단계에서 이 범위의 누락 표본을 확인한다.

[320px 공지/검색 탐색 측정](narrow-controls-audit/measurements.json)에서는 문서 가로 넘침은 없었다. 영어 공지는 Fieldset이250px로 늘어나 검색 패널의 오른쪽 안쪽 여백을 일부 사용한다. 글자 자체 잘림은 관찰되지 않았다. 이것만으로 모든 태그·키보드 초점 경계를 적합하다고 판단하지 않는다.

## R-Q1 날짜 팝오버

날짜 버튼 기준으로 펼치는244px 달력이 예약창의320/360px 상태에서 오른쪽으로 넘친다. 320px 창288px에 내부 스크롤336px, 360px 창324px에 내부 스크롤336px다. 추천은 실제 넘침만큼 안쪽으로 옮기고 오른쪽12px를 남기는 것이다. 390px는 위치 그대로다. 숫자·달력 크기·날짜 선택 동작은 유지한다. 일반 폼 DatePicker 전체를 같은 위치로 옮기지 않는다.

비교는 현재 앱의 DOM에서 위치만 임시 보정했다. 비교 당시 미확인했던 실제 구현·경계·날짜 선택은 승인 후 검증했고 아래 실제 적용 기록에 구분했다.

## R-Q2 예약 상세

로컬 예약1건으로 확인했다. 기존 내용의 최소320px가 모바일390px Dialog 안쪽303px보다 넓어서 scrollWidth368px가 된다. 영어 항목명은65px보다 긴 단어가 값을 침범한다.

추천은 모바일에서만 최소폭을 풀고 긴 값의 줄바꿈을 허용하는 것이다. 항목명은 줄어들지 않게 하고 영어80px·한국어65px를 사용한다. 행동 행에 wrap을 허용하여 버튼이 부족한 폭에서 다음 줄로 이동한다. 글자 크기·색·삭제 동작은 그대로다. 한·영 데스크톱 창 폭368/434px는 유지하며 영어 항목명 개선은 데스크톱에도 적용한다.

비교 당시 긴 내용은 미확인이었다. 이후 긴 제목·목적·이메일과 낮은 창을 검증했고 아래 실제 적용 기록에 구분했다. 반복 횟수·날짜/시간 등 데이터 내용과 삭제 로직은 수정하지 않는다.

## 근거와 한계

[측정 기록](reservation-boundary-comparison/measurements.json): 날짜3폭×전후=6상태, 상세2언어×2폭×전후=8상태, 총14장. 실제 로컬 STAFF 세션·프로덕션 빌드에서 수집한 임시 DOM 제안이다. 상세 비교용 로컬 예약은 만들고 finally에서 삭제했다. 외부 환경은 사용하지 않았다.

위 임시 비교는 승인 전 제안 자료다. DS-026 입력 폭에 이어 팝오버·상세도 DS-029·030으로 적용했으며 실제 검증은 아래 기록을 따른다.

## 실제 적용·검증

- DS-029는 예약 사용처의 calendarClassName으로 작은 창에서만 위치를 조정한다. 90vw 창 안의 왼쪽패딩28px+현재 날짜 라벨/간격64px+달력244px+오른쪽12px를 기준으로 넘침을 보정한다. 창 크기가 변하면 CSS가 다시 계산한다. 일반 편집기의 DatePicker 위치는 유지했다. 이 사용처의 라벨·달력 치수가 바뀌면 함께 재검토한다.
- 320/360/390px에서 팝오버 오른쪽이 각각292/330/355.5px로 승인안과 같고 가로 스크롤이 없다. 날짜25일 선택 후 닫힘·새 날짜 표시를 확인했다.
- DS-030의 한·영390/1280px 상세는 승인 폭351/368/434px를 유지한다. 한국어 두 장면은 승인 이미지와 동일하다. 다른 캡처의 배경 스크롤·경계 차이는 전체 일치로 표시하지 않는다. [이미지 대조](reservation-boundary-implementation/image-comparison.json).
- 긴 연속 제목·목적·이메일을 브라우저에서 대입한 한·영320×600px에서도 가로 넘침 없이 삭제 버튼으로 스크롤할 수 있었다. 제목에는 닫기 버튼 공간을 확보했다. 전체 회귀·모든 데이터 조합 검증은 아니다.
- [실제 측정](reservation-boundary-implementation/measurements.json). 새 프로덕션 빌드·핀된 Playwright Linux Chromium·로컬 실API. 임시 예약 생성 후 삭제했으며 삭제 로직 자체는 바꾸지 않았다.
