# 작은 화면과 예약 상태 — 검토 묶음

[실제 비교](reservation-boundary.html) · [현재 DS](index.html) · [계획](PLAN.md)

2026-09-24. DS-026·027 적용 후 새로 확인한 상태를 묶었다. **V-Q1·R-Q1·R-Q2는 제안이며 아직 미확정·앱 미적용**이다.

## V-Q1 검증 범위 제안

공개 화면·예약320 CSS px부터, 행정실 편집·관리1200 CSS px부터를 최소 검증 폭으로 제안한다. 전자는 DS-003 공개 모바일 지원, 후자는 사용자에게 모바일 편집 수요가 없었던 결정과 기존1200/1280/1440px 편집24상태 조사를 잇는다. 기존320px 소개/푸터와 이번 한·영 공지/검색·예약 표본을 근거로 시작하되, 해당 폭 이상의 전체 사이트 통과를 선언하지 않는다. 검증 범위를 합의한 뒤 4·5단계에서 누락 표본을 확인한다.

[320px 공지/검색 탐색 측정](narrow-controls-audit/measurements.json)에서는 문서 가로 넘침은 없었다. 영어 공지는 Fieldset이250px로 늘어나 검색 패널의 오른쪽 안쪽 여백을 일부 사용한다. 글자 자체 잘림은 관찰되지 않았다. 이것만으로 모든 태그·키보드 초점 경계를 적합하다고 판단하지 않는다.

## R-Q1 날짜 팝오버

날짜 버튼 기준으로 펼치는244px 달력이 예약창의320/360px 상태에서 오른쪽으로 넘친다. 320px 창288px에 내부 스크롤336px, 360px 창324px에 내부 스크롤336px다. 추천은 실제 넘침만큼 안쪽으로 옮기고 오른쪽12px를 남기는 것이다. 390px는 위치 그대로다. 숫자·달력 크기·날짜 선택 동작은 유지한다. 일반 폼 DatePicker 전체를 같은 위치로 옮기지 않는다.

비교는 현재 앱의 DOM에서 위치만 임시 보정했다. 실제 구현 방법과320/360 경계·낮은 창·날짜선택 후 닫힘은 승인 후 확인한다.

## R-Q2 예약 상세

로컬 예약1건으로 확인했다. 기존 내용의 최소320px가 모바일390px Dialog 안쪽303px보다 넓어서 scrollWidth368px가 된다. 영어 항목명은65px보다 긴 단어가 값을 침범한다.

추천은 모바일에서만 최소폭을 풀고 긴 값의 줄바꿈을 허용하는 것이다. 항목명은 줄어들지 않게 하고 영어80px·한국어65px를 사용한다. 행동 행에 wrap을 허용하여 버튼이 부족한 폭에서 다음 줄로 이동한다. 글자 크기·색·삭제 동작은 그대로다. 한·영 데스크톱 창 폭368/434px는 유지하며 영어 항목명 개선은 데스크톱에도 적용한다.

이름·이메일·긴 예약명 등의 극단적 내용은 아직 별도 검증하지 않았다. 승인 시 관련 경계를 확인한다. 반복 횟수·날짜/시간 등 데이터 내용과 삭제 로직은 수정하지 않는다.

## 근거와 한계
