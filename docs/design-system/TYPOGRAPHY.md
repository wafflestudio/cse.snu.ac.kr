# 타이포 기반 — 본문 서체 연결 비교

[진행 현황](PLAN.md) · [전후 화면 비교](typography.html) · [방향과 예외](DIRECTION.md)

3-1의 기본 서체 연결은 **DS-006으로 결정하고 앱 CSS에 적용했다.** 공개 본문 5장면에서 승인안과 일치함을 확인했다.
크기·굵기·행간·문단 간격의 역할별 규칙은 3-3에서 이어서 정한다.

## 문제와 결정 T-Q1 → DS-006

일반 UI는 `Pretendard Variable`을 사용한다. 반면 본문 뷰어와 편집기가 공유하는 스타일은
`Pretendard`부터 검색한다. 저장소에 등록된 웹폰트 이름은 `Pretendard Variable`이어서,
이전 Linux 조사에서는 본문에 시스템 폰트 `WenQuanYi Zen Hei`가 사용됐다.

- [웹폰트 등록](../../apps/web/src/assets/pretendard/pretendardvariable-dynamic-subset.css)
- [일반 UI의 서체](../../apps/web/src/app.css)
- [공유 본문 스타일](../../apps/web/src/components/ui/assets/suneditor-contents.override.css)
- [HTMLViewer](../../apps/web/src/components/ui/HTMLViewer.tsx)와 [HTMLEditor](../../apps/web/src/components/form/html/HTMLEditor.tsx)
- [이전 실제 서체 조사](ROLE-AUDIT.md)

**공유 본문 스타일의 기본 서체 목록 맨 앞에 `"Pretendard Variable"`을 추가했다.**
이미 제공하는 웹폰트를 연결하는 변경이다. 새 서체를 도입하거나 메인 슬로건의 Gowun Batang을 교체하는 안은 아니다.
등록되지 않은 이름을 기본으로 두면 운영체제의 대체 서체에 따라 결과가 달라진다.

앱 변경은 공유 본문 스타일의 한 지점이다.

```diff
 .sun-editor-editable {
   font-family:
-    Pretendard, -apple-system, BlinkMacSystemFont, system-ui, Roboto,
+    "Pretendard Variable", Pretendard, -apple-system, BlinkMacSystemFont, system-ui, Roboto,
```

이 코드는 적용한 변경 범위를 보여주는 발췌다.
현재의 본문 14px·행간 2, 색·문단 정렬·폭 지정·패딩은 그대로 비교했다.
이 값들이 최종 타이포 규칙으로 승인됐다는 뜻은 아니다.

## 승인 전 실제 앱에서의 비교 방법

1. 현재 프론트 소스로 프로덕션 빌드를 만들고, 로컬 실 API에 조사 전용 공지를 생성했다.
2. 같은 문서·뷰포트에서 현재 상태를 캡처했다. 첫 문단과 두 번째 문단, 굵은 강조의 실제 폰트는 CDP로 읽었다.
3. 같은 DOM의 `.sun-editor-editable` 컨테이너에만 위 서체 목록을 적용했다. 자손의 글자 크기·스타일은 강제로 덮지 않았다.
4. 폰트 로딩 완료 후 다시 측정·캡처했다. HTML 내용, 기본 크기·굵기·행간·색·패딩, UI의 서체가 그대로인지 확인했다.
5. 같은 공지를 편집기로 열어 반복했다. 공지 편집 저장은 하지 않았으며 조사 전용 공지는 실행 후 삭제했다.

[재현 도구](../../e2e/design-survey/font-comparison.spec.ts)는 기본 E2E 회귀 실행에 포함되지 않는 조사 도구다.
원래 레이아웃에서 서체를 연결했을 때의 차이를 보려는 실험이므로 임의로 폭이나 높이를 고정하지 않는다.
다음 명령은 **적용 전 커밋 `e71c63fc`에서** 승인 전 비교를 재현한다. 현재 적용 후 소스에서 실행하면 이전 기준을 덮으므로 사용하지 않는다. 기존 로컬 조사와 같이 DB가 초기화된다.

```sh
pnpm e2e --config design-survey.config.ts --grep '본문 서체 연결 전후 비교'
```

여섯 장면 모두 기본 본문은 실제로 Pretendard Variable로 전환됐다. 이번 표본에서는 전체 본문 높이와
첫 두 문단의 줄 수가 유지됐지만 줄이 끝나는 위치는 달라졌다. 다른 콘텐츠에서도 높이가 같다는 보장은 아니다.

본문 첫 문단의 줄 수는 텍스트 Range의 줄 위치로 측정했다. 전체 본문 높이는 제목·문단·목록·표를
모두 포함하고, 편집기는 자체 최소 높이와 패딩의 영향도 받는다. 숫자를 새 토큰으로 사용하지 않는다.
원자료는 [measurements.json](font-comparison/measurements.json)에 있다.

관찰할 점:

- 같은 크기·굵기 지정에서도 글자 모양과 강조의 인상이 달라진다. 전후 이미지에서 제목과 굵은 글씨가 더 뚜렷해진다.
- 한영 혼합 문장의 줄 끝과 영어 단어 간격이 달라진다. 기존 양끝 정렬은 유지했다. 정렬·읽기 밀도는 3-3에서 별도로 검토한다.
- 짧은 영어 인사말의 모바일 영역은 내용에 맞춰 폭이 정해진다. 서체 연결로 실측 폭도 달라진다.
  처음 작성한 조사 도구의 ‘모든 본문 실측 폭은 동일해야 한다’는 가정이 이 표본에서 실패해,
  폭을 고정하는 대신 실제 변화를 기록하도록 수정했다. 앱 배치 코드는 변경하지 않았다.
- 768px에서 기존 페이지 최소 폭에 의한 넘침이 남는다. 서체 연결로 공개 배치 문제까지 해결됐다고 보지 않는다.

## 함께 발견한 기존 차이 — Q-09

작성자가 `font-size:18px`를 지정한 표본은 읽기 화면에서 18px, 편집기에서 14px로 렌더됐다.
서체 연결 전후 모두 같았다. 편집기 DOM에는 `font-size:18px` 속성이 남아 있지만 계산된 크기는
14px다. 따라서 ‘작성자 크기가 읽기·편집에서 모두 보존됐다’고 처리하지 않는다.

읽기 화면은 [prepareHtmlForViewer](../../apps/web/src/serverFns/prepareHtmlForViewer.ts)에서
인라인 스타일을 nonce가 있는 스타일 규칙으로 옮긴다. 편집기는 기존 HTML을 SunEditor에 직접 넣는다.
편집기 로드에서 `style-src-attr: inline` 위반을 확인했다. 이는 인라인 스타일이
[CSP 설정](../../apps/web/src/utils/csp.ts)에 막히는 연결부를 가리킨다. 원자료에 위반 유형을 기록했다.
서체 연결에 의해 새로 발생한 문제가 아니라 읽기·편집 연결부의 후속 수정 대상이다.
사용자 요청에 따라 이 문제는 기록만 남기고 현재 수정하지 않는다. 에디터의 서체·서식 차이는 이번 디자인 변경의 완료를 막지 않는다.

## 이번 실행 환경의 제한

정식 진입점의 선행 명령 `pnpm api:up`에서 Docker 이미지 메타데이터 확인이 프록시 연결 시간 초과로
실패했다. 접근 거부나 인증 만료로 진단하지 않았다. 프록시 설정·애플리케이션 네트워크 코드는 변경하지 않았다.

외부 다운로드 없이 기존 로컬 API 이미지 `73f246951a6f`와 설치된 의존성, 핀된 Playwright 이미지를
사용해 탐색 실행했다. 중지되어 있던 로컬 DB·검색 컨테이너를 다시 시작했고, 러너는 API 컨테이너와
네트워크 공간을 공유해 localhost의 실 API를 사용했다. 프론트는 현재 소스로 다시 빌드했다.
API 명세와 저장소의 생성 타입이 일치함을 확인했다. 임시 실행 설정은 `/tmp`에서 사용했다.

**백엔드 이미지의 이번 소스 재빌드를 검증한 결과나 정식 E2E 전체 통과가 아니다.**
정식 실행 경로의 회귀 확인은 5단계 통합 검증에 남긴다. 이 환경 문제로 디자인 작업 범위를 넓히지 않는다.
측정 도구의 폭 가정과 작성자 크기 선택자를 보완한 재실행에는 같은 프론트 빌드·시드를 재사용했다.
이번 실행은 새로운 서체 연결의 실제 렌더 차이를 검토할 근거로 사용한다.

## 실제 CSS 적용 확인

`DESIGN_FONT_MODE=applied`를 조사 러너 컨테이너에 전달해, 브라우저 스타일 덮어쓰기 없이
새 프로덕션 빌드를 확인했다. 로컬 API 이미지 등 실행 환경의 한계는 위와 같다.

- 긴 한영 공지 1280·390·768px, 영어 인사말 1280·390px의 **본문 이미지 5개가 승인한 연결안과 바이트 단위로 일치**했다.
- 실제 렌더 서체는 Pretendard Variable이며 기본 크기·행간·색·패딩·본문 폭·높이가 승인 견본과 일치했다.
- [적용 결과 원자료](font-implementation/measurements.json)와 같은 폴더의 `*-applied-body.png` / 전체 화면을 보존했다.
- 사용자 요청에 따라 에디터 내부 동작·서식 차이·CSP와 Sonner는 검증·수정 범위에서 제외했다.
  진행 중이던 편집기 로직과 관련 동작 테스트 변경도 철회했다.
- 기존 스크린샷 기준은 갱신하지 않았다. 전체 회귀 통과를 의미하지 않는다.

기본 서체 연결에 대한 추가 결정은 필요 없다. 다음은 [색상 비교](colors.html)이며,
타이포 위계·본문 밀도는 3-3에서 연결된 서체를 기준으로 다룬다.
