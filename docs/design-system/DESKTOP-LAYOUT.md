## 이번에 확인한 범위

DS-003의 행정실 데스크톱 중심 범위에서 1200·1280·1440px를 실측했다.
공지 빈 폼·제목/첨부/고정 만료일 입력 상태, 교수 한국어·영어 입력 탭, 직원 폼,
슬라이드·중요 안내·이미지 팝업 관리의 8개 상태 × 3개 폭 = **24개 상태**다.

실제 로컬 STAFF 세션, 새 프론트 프로덕션 빌드, 고정 브라우저 시각 2026-09-24 12:00 KST를 사용했다.
입력·로컬 파일 선택·교수 학력 항목 추가만 수행했고 게시·저장·삭제는 하지 않았다.
관리 UI 언어는 한국어이며 교수의 영어 입력 탭을 별도 확인했다. 영어 관리 UI 전체를 검증한 것은 아니다.
SunEditor는 폼 안의 기존 영역만 보고 내부 서식·서체·동작은 조사·수정 범위에서 제외했다.

[24개 상태의 실측 기록](desktop-layout-audit/measurements.json).

## 결과와 유지할 기준

표본의 페이지 가로 넘침은 없었다. 서로 다른 간격이 있다는 이유만으로 변경하지 않는다(DS-016).
새 화면은 가장 가까운 기존 폼 유형과 필드 역할을 재사용한다. 모든 필드를 같은 여백으로 통일하지 않는다.
아래는 사용처를 확인한 **기존 역할·예외의 기록**이며 새로운 강제 간격 스케일이 아니다.

| 책임·역할 | 현재 값 | 확인한 사용처와 해석 |
| --- | --- | --- |
| 라벨 → 입력 | 주로 8px | 일반 텍스트·반복 입력·날짜. Fieldset 기본 titleSpacing=2 |
| 라벨 → 묶음 | 12px | 공지 태그·첨부·게시 설정, 교수 구분. 단일 입력보다 큰 묶음의 제목 간격 |
| 가까운 필드 사이 | 20px | 교수/직원의 이름·직함·연락처. 같은 정보 묶음의 반복 입력 |
| 반복 목록 사이 | Fieldset 아래 10px, 각 행 아래 10px | 학력·연구 분야·경력·주요 업무. 행 내부 간격과 바깥 Fieldset 간격의 책임 구분 |
| 글 작성의 큰 필드 | 24·32px | 공지 제목·보조 제목·태그는 32px, 내용·첨부·게시 설정은 24px. Fieldset.Title 기본 24px와 공지의 32px는 기존 맥락별 예외 |
| 프로필의 구획 | 40·44·48px | 소속/위치 뒤 40px, 구분 뒤 44px, 사진 뒤 48px. 40px로 숫자만 통일하지 않음 |
| 관리 표 | 행 상하 12px, 표 바깥 아래 32px | 슬라이드·중요 안내. 고정 열과 줄임표 제목의 기존 책임 유지 |
| 저장/취소 영역 | Form.Action | 개별 필드의 margin으로 배치를 대신하지 않고 공용 행동 영역 사용 |

Fieldset과 Form.Section은 비슷한 간격 옵션을 쓰지만 서로 다른 구조의 책임이다. 독립 컴포넌트를 합치지 않는다.
4·16px 등 옵션이 존재한다는 사실과 이번 대표 화면에서 실제 사용한 값은 구분한다.

기존 모바일 교수 폼·첨부 넘침(B-03/B-07)은 DS-003에 따라 모바일 편집 최적화의 완료 조건으로 삼지 않는다.
교수 전화/팩스의 672px 고정 묶음은 1200px에서 본문 틀 640px보다 32px 넓다. 현재 여유 공간 안에 놓여 페이지 넘침이나 다른 조작과의 충돌은 관찰되지 않았다. 폼 폭을 더 줄이는 경우 재검토한다.
첨부 행은 기존 520px/높이 30px다. 현재 2줄 파일명 표본만 확인했으며 임의의 더 긴 이름·삭제 조작·큰 글자 검증을 완료했다는 뜻은 아니다.
입력 오류의 위치·초점, 업로드·저장 중 상태 등은 4단계 컴포넌트 검토로 남긴다.

## 이번 처리

이 표본을 근거로 폼 간격이나 고정 폭을 새로 정규화하지 않았다.
필드 내부·필드 사이·묶음 사이·페이지 여백의 책임을 구분해 문서에 남겼다.
공개 화면에 남은 통합검색 태그는 별도 비교한다. 3-6의 [모서리·크기·그림자 소스 조사](SHAPES.md)는 병렬로 정리했고 대표 렌더 확인은 남아 있다.
