## DS-001. 기존의 시각적 특징을 보존한다

- 결정일: 2026-09-22.
- 연결 질문: J-01. 어떤 특징을 남길까?
- 근거: 변경 전 화면을 제시하고 어두운 큰 면·주황·원과 선·접힌 모서리의 보존 여부를 질문했다.
  사용자는 “ㅇㅇ 유지하고 싶은 특징이야. 바꾸고 싶은건 없어.”라고 답했다.

**어두운 큰 면, 주황, 원과 선, 접힌 모서리를 보존할 시각적 특징으로 정한다.**
이 특징을 다른 시각 언어로 교체하는 방향은 이번 작업의 출발점으로 삼지 않는다.
이후 기반 규칙과 컴포넌트 제안에서도 이 특징이 이어지는지 확인한다.

이번 결정은 특징의 보존에 관한 것이다. 현재의 모든 색상 코드·크기·간격·배치를 그대로 고정한다는
결정이나, 세부 시각 변경을 일괄 허용한다는 결정으로 확대하지 않는다.
읽기·조작 문제를 해결하기 위한 변경 범위는 DS-002, 작은 화면에서 보장할 작업은 DS-003에서 결정했다.
본문 서체, 문구 원칙, 개별 컴포넌트 규칙도 아직 결정하지 않았다.

앱 변경은 없다. 후속 제안은 보존할 특징과 해결할 문제를 함께 설명하고, 실제 화면으로 비교한다.

## DS-002. 읽기·조작 문제를 해결하기 위한 세부 시각 변경을 허용한다

- 결정일: 2026-09-22.
- 연결 질문: J-02. 화면 변화는 어디까지 허용할까?
- 근거: 기존 인상과 정보 구조를 유지하면서 대비, 본문 서체 연결과 필요한 행간·간격,
  키보드 초점 표시, 좁은 화면에서 넘치는 배치를 조정하는 방향을 제시했다.
  사용자는 “ㅇㅇ 맞아”라고 답했다.

**DS-001의 특징과 기존 정보 구조를 유지하면서, 읽기·조작 문제를 해결하는 데 필요한
색·서체·행간·간격·배치 변경을 허용한다.**

대상은 조사에서 확인한 대비(P-02), 서체 연결(P-01), 초점 표시(P-03), 화면 넘침(P-04~P-06) 등이다.
문제와 연결된 변경 이유를 설명하고, 구체적인 변경안은 적용 전에 실제 화면으로 함께 비교한다.
합의한 변경안의 구현·검증은 이어서 완료한다.

이번 결정으로 새 색상 값, 본문 크기, 간격 단계, 브레이크포인트가 확정되는 것은 아니다.
작은 화면에서 보장할 작업 범위와 P-06의 우선순위는 DS-003을 따른다. 문구 원칙과 개별 컴포넌트 규칙도 후속 검토 대상이다.
현재 앱 변경은 없다.

## DS-003. 공개 기능은 모바일을 지원하고 편집·관리는 데스크톱 중심으로 설계한다

- 결정일: 2026-09-22.
- 연결 질문: J-03. 작은 화면에서 어디까지 할 수 있어야 할까?
- 근거: 공개 기능의 모바일 지원과 데스크톱 중심의 편집·관리 설계에 대해 사용자는
  “2번이 보다 가까워. 편집 관리는 행정실에서 사용하는데 모바일에 대한 니즈는 없었어.”라고 답했다.

**공개 탐색·읽기·검색·일반 이용자의 예약 흐름은 모바일을 지원하고,
행정실이 사용하는 콘텐츠 편집·관리는 데스크톱 작업에 맞춰 설계·검증한다.**

- 모바일 편집 전용 배치 최적화는 v1의 필수 완료 조건으로 두지 않는다.
  P-06의 교수 폼·첨부 행 모바일 넘침은 관찰 기록을 유지하되 현재 개선 우선순위에서 내린다.
- 데스크톱 편집·관리의 가독성, 키보드 초점, 입력·오류·저장 흐름은 계속 검토한다.
  공용 컴포넌트를 쓰는 일반 이용자 기능은 모바일 검증 대상에 남는다.
- 로그인 여부나 `form` 컴포넌트 사용 여부만으로 관리 화면을 분류하지 않는다.
  예를 들어 일반 이용자의 예약 입력은 행정실 콘텐츠 편집과 목적이 다르다.
- 이 결정은 기존 모바일 편집 기능을 제거하거나 접근을 차단한다는 뜻이 아니다.
  별도의 접속 안내도 자동으로 추가하지 않는다.

데스크톱의 최소 지원 폭과 구체적인 배치 전환값은 레이아웃 비교에서 정한다.
기존 루트의 1200px 최소 폭이나 1280px 테스트 표본을 승인된 지원 기준으로 간주하지 않는다.
앱 변경은 없다.

## DS-004. 주요 실행은 짙은 중립색을 기본으로 한다

- 결정일: 2026-09-22.
- 연결 질문: H-Q1. 일반적인 주요 실행의 기본 강조.
- 근거: 실제 버튼 사용처의 혼용과 [A/B 견본](hierarchy.html#actions)을 비교했다.
  사용자는 “A 좋아”라고 답했다.

**추가·저장·게시·예약 같은 일반적인 주요 실행은 짙은 중립색을 기본으로 한다.
주황은 기존 그래픽과 선택 표시에서 유지한다.**

이 방향을 적용하면 현재 주황인 일부 추가·예약 버튼이 바뀐다. 컴포넌트 단계에서 실제 작업
묶음의 완료·보조·위험 행동을 구분하고 사용처를 정리한다. 기존 variant 이름만 일괄 치환하지 않는다.

견본의 색상 코드·크기, 호버·초점·비활성 상태, 위험 행동, 어두운 배경 위의 대비안은 이번에
확정하지 않았다. H-01~H-03의 역할 제안 전체를 별도로 승인한 것으로도 기록하지 않는다.
기반 규칙의 구체적인 값은 후속 화면 비교에서 정한다. 앱 변경은 없다.

## DS-005. 짧은 행동명과 차분한 존댓말로 행동·대상·결과를 설명한다

- 결정일: 2026-09-22.
- 연결 질문: W-Q1. 문구의 기본 방향.
- 근거: [실제 문구 비교](COPY.md)를 제시하고, 공지 편집·교과목 수정의 ‘변경사항 저장’,
  편집 취소 확인창의 ‘계속 편집 / 나가기’, ‘제목을 입력해 주세요.’를 비교했다.
  사용자는 “ㅇㅇ 좋아”라고 답했다.

**버튼은 ‘저장·게시·예약’처럼 짧은 행동명을 기본으로 하고, 실제 행동과 대상을 명확히 쓴다.
안내는 ‘~해 주세요’, 설명·완료는 ‘~합니다 / ~했습니다’의 차분한 존댓말을 사용한다.**

짧게 쓰더라도 ‘변경사항 저장’, ‘계속 편집’처럼 행동을 구분하는 데 필요한 의미는 생략하지 않는다.
‘확인’으로 저장·삭제·이탈을 대신하지 않고, 버튼·확인·완료 안내가 같은 결과를 설명하게 한다.
‘성공했습니다’보다 무엇이 바뀌었는지를 쓴다.

이 결정은 UI 문구 방향에 대한 합의다. 작성된 게시물 본문이나 기관의 공식 명칭을 일괄 고치지 않는다.
각 사용처의 한국어·영어, 입력·오류·처리 중 동작은 적용 시 함께 대조한다.
COPY.md의 미확인 오류 흐름, 새 기능, 모든 예시의 세부 표현을 일괄 승인한 것으로 확대하지 않는다.
구체적인 적용은 4단계의 행동·폼·피드백 검토와 연결한다. 현재 앱 문구 변경은 없다.

## DS-006. 본문과 편집기의 기본 서체를 Pretendard Variable로 연결한다

- 결정일: 2026-09-22.
- 연결 질문: T-Q1. 등록된 본문 기본 서체 연결.
- 근거: [실제 앱 6장면 비교](typography.html)에서 글자 모양·줄바꿈 위치·높이를 확인했다.
  사용자는 “ㅇㅇ 좋아”라고 답했다.

**본문 뷰어와 편집기가 공유하는 font-family의 첫 항목을 `"Pretendard Variable"`로 정한다.**
일반 UI에 이미 등록된 웹폰트를 본문에서도 사용한다. 메인 슬로건의 Gowun Batang은 유지한다.
이번 결정은 기본 서체 연결이며 크기·굵기·행간·문단 정렬·폭·간격의 최종 규칙은 후속 비교한다.
작성자가 별도로 지정한 서식을 기본값으로 강제 덮어쓰지 않는다.

적용·검증 상태와 함께 발견한 기존 편집 서식 문제 Q-09는 PLAN.md와 TYPOGRAPHY.md에서 추적한다.

## DS-007. 브랜드 주황 #ff6914와 그 위 흰 글씨를 유지한다

- 결정일: 2026-09-23.
- 근거: 사용자는 주황 hex 변경이 디자인 분위기를 크게 바꾸므로 불가하다고 명시했다. C-Q1 A의 검은 글자도 기존 인상과 달라 거절했다.

브랜드 주황은 `#ff6914`를 사용한다. 대비 개선을 이유로 다른 주황 값으로 대체하지 않는다.
C-Q1의 A(짙은 글자)·B(주황 면 변경)는 적용하지 않는다. 기존 개별 호버 상태를 일괄 변경하라는 결정으로 확대하지 않는다.
사용자는 이후 “ㅇㅇ 주황 배경에 흰색 글씨는 유지하자”라고 확정했다. 기존 조합을 유지하고 대비 개선은 보류한다.
외곽선·halo·글자 영역 분리·고대비 보기 등을 이번 작업에 추가하지 않는다.
흰색 #ffffff는 약 2.88:1, 기존 선택 글자의 #fafafa는 약 2.76:1로 대비 미달이 남는다.
이 결정은 디자인 보존을 위한 알려진 한계 수용이며 WCAG 대비 기준 충족이나 문제 해결로 표시하지 않는다.
DS-004의 주요 실행은 짙은 중립색을 기본으로 한다는 역할 방향도 유지한다.

## DS-008. 입력 예시·보조 버튼·입력 초점의 중립색을 정한다

> 현재 규칙: 입력 예시·보조 버튼 색은 유지한다. 추가 초점 외곽선은 사용자 요청으로 DS-012에서 철회했다. 아래는 당시 결정·검증 기록이다.

- 결정일: 2026-09-23.
- 연결 질문: C-Q2. [현재/제안 견본](neutral-focus.html)에 사용자는 “ㅇㅇ 좋아”라고 답했다.

| 적용 역할 | 규칙 |
| --- | --- |
| 공용 form/Text·TextArea의 입력 예시 | neutral-500 #737373 |
| ui/Button secondary의 글자 | neutral-600 #525252 |
| 공용 form/Text·TextArea의 초점 | :focus-visible에 neutral-700 #404040, 2px solid outline, offset 2px |

기존 입력값·크기·간격·버튼 배경·호버 배경·비활성 처리는 유지한다. 주황 배경/흰 글씨는 DS-007을 따른다.
이 규칙을 다른 모든 중립색 글자·검색창·어두운 면의 초점에 일괄 확대하지 않는다. form과 ui의 독립 구현도 유지한다.
앱 클래스에 적용했다. 실제 공지 제목 입력과 예약 입력/textarea(1280·390px), secondary 기본·호버 색을
새 프론트 프로덕션 빌드와 기존 로컬 API에서 확인했다. [적용 원자료](neutral-implementation/measurements.json).
모바일 예약창에서 관찰한 가로 넘침·초점 일부 잘림은 Q-10으로 분리했다.
정식 전체 회귀나 모든 사용처 검증이 아니며, 기능 로직과 에디터 내부는 변경하지 않았다.

## DS-009. 색 체계를 네 계열과 역할별 사용 규칙으로 구성한다

- 결정일: 2026-09-23.
- 연결 질문: C-Q3. [누적 DS](index.html#colors)에 제시한 전체 구성에 사용자가 “응응”으로 동의했다.

브랜드 주황 / 중립색 / 정보 링크 / 오류의 네 계열을 기본 구성으로 삼는다.
기존 색에서 출발해 배경·글자·경계·행동의 역할별 사용 규칙을 정한다.
성공·경고 계열은 실제로 필요한 표현을 검토할 때 정하며, 이번에 새 색을 추가하지 않는다.
DS-007·008은 확정 규칙으로 유지한다. 기존 팔레트의 개수·모든 값이나 미확정 역할을 일괄 승인한 결정은 아니다.

후속 작업은 배경·본문·경계의 기본값과 예외, 링크·오류·상태 조합의 순서로 이어간다.

## DS-010. 중립색을 배경·글자·내용 경계의 역할로 선택한다

- 결정일: 2026-09-23.
- 연결 질문: C-Q4. [역할 견본과 실제 교과목 비교](neutral-roles.html)에 사용자는 “ㅇㅇ 좋아”라고 답했다.

[중립색 역할표](NEUTRAL-ROLES.md)를 기본 사용 기준으로 확정한다.
밝은 면은 white / neutral-50 / neutral-100을 기본 / 약한 구분 / 묶음으로 사용한다.
밝은 면의 주요·설명·보조 글자는 neutral-950 / 700 / 500, neutral-100·200 위 작은 보조 글자는 600이다.
일반 페이지의 어두운 큰 면 900과 카테고리의 850을 유지하며 그 위 글자는 white / 400으로 구분한다.
내용 구분선은 200, 더 뚜렷한 내용 경계는 300이다. 입력 외곽선의 최종 규칙을 이 결정으로 대신하지 않는다.

첫 적용 범위는 공유 CourseList의 구분·번호·학점·학년, CourseToolbar의 비선택 보기 방식,
CoursesPage의 영어 약어 설명이다. neutral-400 → 500으로 변경하며 선택된 보기 방식의 800은 유지한다.
학부·대학원은 같은 컴포넌트를 사용하므로 둘 다 영향을 받는다.
