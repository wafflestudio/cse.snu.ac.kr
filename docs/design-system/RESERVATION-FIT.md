# 예약창 입력 폭 — S-Q1

[현재 DS](index.html) · [실제 비교](reservation-fit.html) · [형태 역할표](SHAPES.md)

## 먼저 완료한 것

DS-025 영어 통합검색 최소 160px 열 적용을 완료했다. 한·영 대표 6장면이 승인 견본과 일치했고
키보드 선택·포인터 해제·URL·검색 결과 연결을 확인했다. [실제 적용](search-grid.html).
이번 비교는 3-6 크기 검토에서 기존에 기록한 모바일 예약창 넘침 Q-10을 다시 확인한 것이다.
예약은 일반 이용자의 공개 기능이므로 DS-003의 모바일 지원 범위에 속한다.

## 문제와 원인

390px 창에서 예약 모달 폭은 351px(90vw), 안쪽 여백은 좌우 28px라 콘텐츠 공간은 295px다.
단체 이름·이메일·전화번호·지도교수의 전용 Fieldset은 `w-88`(352px)로 고정돼 있다.
이 때문에 입력칸 오른쪽이 잘리고, 모달 내부 가로 스크롤 폭이 380px로 늘어난다.
사용 목적 칸은 이미 내용 폭 295px에 맞는다.

## 제안과 이유

**기존 352px 폭에 부모 폭을 넘지 않는 최대 폭 제한을 추가한다.**
이 네 필드는 좁은 창에서만 내용 폭에 맞춰 줄어들고, 공간이 충분하면 기존 352px를 유지한다.
기존 입력 높이·글자·색·간격·모달 크기·사용 목적 칸은 유지한다.
변경 소유자는 예약창 내부의 전용 Fieldset이다. 공용 Dialog나 입력 API, 예약 기능 로직까지 바꿀 필요는 없다.

이유는 사용 가능한 창 안에서 입력칸 전체를 보고 조작하기 위해서다.
새 최소 입력 폭을 정하거나 데스크톱 밀도를 바꾸는 제안은 아니다.

## 실제 비교에서 확인한 것

- 한·영 390px: 네 입력칸이 352→295px, 모달 내부 스크롤 폭이 380→351px로 맞는다.
- 한·영 1280px: 입력 352px·모달 408px를 유지하며 **전후 이미지가 바이트까지 동일**하다.
- 한국어 390px 날짜 팝오버 펼침: 244px 달력이 현재 표본에서 모달 안에 보이고, 제안 후 모달 내부 가로 넘침이 없다.
- 모달의 세로 크기·닫기·취소·예약 버튼 위치는 이 비교에서 유지됐다. Escape 닫기를 확인했고 저장은 하지 않았다.

새 프로덕션 빌드 + 로컬 실 STAFF 세션, 고정 시각 2026-09-24 12:00 KST에서
브라우저의 해당 Fieldset에 `max-width:100%`만 임시 적용했다. **앱 미적용**이다.

이번 표본은 390/1280px이며 최소 지원 폭을 확정한 것이 아니다. 승인 후 더 좁은 폭의 팝오버와
짧은 화면 높이에서 필요한 경계·조작 접근만 확인한다. 전체 예약 동작을 재검증하는 범위는 아니다.
