# 폼 오류 안내 — DS-027 적용

[검토 묶음과 실제 견본](form-modal-review.html#errors) · [현재 DS](index.html) · [계획](PLAN.md)

2026-09-24. **FO-Q1 A 승인·적용.** 기존 하단 요약과 검증 규칙을 유지하며 해당 필드 아래에도 오류를 표시한다. 아래 선택지는 승인 전 비교 기록이다.

## 문제와 변경 이유

`Form.Action`은 오류를 문자열 목록으로 모아 맨 아래 취소·게시 버튼 옆에 표시한다. `Text`·`TextArea`·`Fieldset`에는 필드별 오류 안내가 없다. 공지·교수·직원 폼은 `shouldFocusError:false`다.

현재 공지 작성 1280px의 빈 제출에서 “제목을 입력해주세요.”와 “내용을 입력해주세요.”가 표시됐다. 제목 묶음은 문서 y=353px, 오류 요약은 y=1498px로 약 1145px 떨어져 있다. 제출 뒤 scrollY=1154px이고 활성 요소는 body였으며, 위쪽 제목에 초점이 이동하지 않았다. 이는 이 표본에서 관찰한 결과이며 모든 폼의 동작을 선언하지 않는다.

사용자가 고칠 필드에서 오류 원인을 함께 읽도록 하는 것이 A의 목적이다. 단순히 붉은 면적을 늘리거나 입력에 새 외곽선을 추가하려는 변경이 아니다.

## 선택지

| 안 | 표시 | 이점 | 한계 |
| --- | --- | --- | --- |
| A 추천 | 하단 요약 유지 + 해당 필드 아래 동일한 오류 문장 | 수정할 위치와 안내가 연결됨 | 문구 중복, 오류일 때 필드 높이 약 20px 증가. 맨 아래 안내 배치는 기존 유지 |
| B | 필드 유지 + 하단 요약을 버튼 위 독립 전폭 행으로 이동 | 안내와 버튼의 공간 분리 | 위쪽 입력과 안내가 멀다는 문제는 남음 |

A는 기존 오류 목록의 13px·행간·red-600을 복사하고 필드 아래 간격 4px만 더했다. B는 기존 목록을 행동 행 위로 옮기고 아래 간격 12px를 뒀다. A의 기존13px·red-600·위4px가 DS-027로 확정됐다. B의 하단 배치 변경은 적용하지 않았다. 경계·배경·입력 초점과 기존 오류 문구는 유지한다. 두 안을 결합하고 싶다면 그 의사도 받을 수 있다.

## 구현·검증 경계

- 비교는 한국어 공지 작성 1280px의 기존·A·B 3상태, 제목 주변·하단·전체의 9장이다. [측정](form-errors-comparison/measurements.json). 실제 STAFF 세션의 빈 제출이며 저장하지 않았다.
- 브라우저 DOM만 임시 변경했다. 내용 안내는 사이트의 외부 Fieldset에 붙였고 SunEditor 내부·서식·CSP는 변경하지 않았다.
- 검증 규칙·제출·자동 초점·자동 스크롤은 선택 범위 밖이다. 이들 동작의 변경 필요는 별도 과제로 남긴다.
- 공유 Form 사용처의 실제 필드 키에 연결했다. 중첩 필드·언어 탭은 평탄화된 문구로 위치를 추측하지 않는다. 화면에 숨겨진 필드 오류 처리와 `aria-describedby`·`aria-invalid` 등 안내 연결은 실제 구현에서 확인한다.
- 기존 하단 오류 요약의 live region 동작은 변경하지 않았다. 실제 적용에서는 Text·TextArea·Dropdown과 외부 Fieldset에 aria-invalid/describedby를 연결했다. SunEditor 내부 연결은 제외한다.
- `Form.Action`을 쓰지 않는 교과목 편집의 기존 기능 문제 Q-08까지 자동으로 수정 범위를 넓히지 않는다. ui/form 분리도 유지한다.
- 행정실 편집의 모바일 최적화는 DS-003대로 v1 필수 범위에서 제외한다.

## 실제 구현과 검증

- DOM 래퍼를 추가하지 않는 오류 컨텍스트와 `Fieldset.errorName`으로 **21개 폼 모듈의42개 필드 묶음**에 연결했다. 오류가 없으면 기존 배치를 유지한다. Text/TextArea/Dropdown은 같은 필드키일 때만 안내를 참조한다.
- 공지·뉴스·세미나·교수·직원·연구실/그룹/센터·학사 연혁/장학·소개/입학 등의 기존 메시지 있는 필드를 대상으로 했다. 예약의 메시지 없는 검증과 Form.Action을 사용하지 않는 교과목 폼은 확대하지 않았다.
- 공지 빈 제출의 제목 안내가 승인 A 견본과 일치하고, 제목 수정 시 필드 안내·하단 해당 항목·오류 속성이 해제되며 내용 오류는 남는 것을 확인했다. HTML 안내는 사이트 외부 Fieldset에만 추가했다.
- 직원 한·영 탭에서 해당 필드키의 오류만 나타나며 수정 후 해제된다. 숨겨진 언어의 오류는 **기존 RHF 오류 상태에 남아있는 동안** 하단 요약에 남는다. 다음 제출은 언마운트 필드의 오류를 지우는 기존 동작이며 재진입만으로 재검증하지 않는다. 검증 로직은 변경하지 않았다.
- 전체 폼 비교는 에디터 툴바의 일부 픽셀·전체 캡처 높이1px 차이가 발생할 수 있어 에디터 일치를 완료 조건으로 추가하지 않았다. 새 안내 위치·값·제목 견본과 상태 연결을 확인했다. [실제 기록](form-errors-implementation/measurements.json).
- 공지/직원 영구 E2E에 오류 안내와 해제·언어별 연결을 추가했다. 나머지 필드 각각의 브라우저 전수 상태를 완료한 뜻은 아니다.

검증 실행: 핀된 Playwright1.57.0 Linux Chromium·새 프로덕션 빌드·기존 로컬 실API에서 공지/직원 영구 E2E2개 모두 통과했다. 전체 회귀를 재실행한 결과는 아니다.
