# 첨부 파일명·삭제 상태 — DS-031·032 적용

[실제 견본](file-controls.html) · [현재 DS](index.html) · [계획](PLAN.md)

2026-09-24, 4단계. 사용자 “1 B, 2 적용”으로 **UP-Q1 B·UP-Q2를 승인**했다. DS-031·032로 적용했다. 아래 비교표는 승인 전 검토 기록이다.

## 먼저 적용·확인한 것

- DS-020을 폼 체크·라디오·드롭다운·날짜·파일/이미지 선택과 삭제에 연결했다. [8개 초점 표본과 키보드 확인](form-controls-implementation/measurements.json).
- 파일/이미지 선택 input은 sr-only로 유지해 네이티브 Tab/Space 접근이 가능하다. 파일 삭제는 파일명이 포함된 이름을 제공한다. 공지 작성의 영구 E2E에서 Tab→Space→파일 선택→Tab→Enter 삭제를 확인했다. 이 표본의 파일 선택은 Space로 확인했고 Enter 선택까지 검증 완료로 표시하지 않는다.
- Button md와 ui/form Dropdown의 정확히 같은 rem 패딩을 기존 간격 유틸리티로 연결했다. 기본 크기 변경은 없다.

## UP-Q1 긴 첨부 파일명

변경 전 FilePickerRow는520px×30px 고정이며 파일명 p는 여러 줄로 감길 수 있다. 긴 이름의 높이가 행보다 커지면 인접 행을 침범한다. 현상은 행 높이 책임의 문제이며 파일명 자체를 바꾸거나 파일 처리를 수정할 이유는 없다.

| 안 | 처리 | 이유·한계 |
| --- | --- | --- |
| A 미선택 | 최소높이30px, 내용에 따라 높이 증가, 위아래5px, 긴 단어 줄바꿈, 삭제 아이콘 크기 유지 | 전체 이름으로 파일 구분. 긴 이름이 많으면 목록 높이가 늘어남 |
| B 확정 | 한 줄30px 유지, 이름만 ellipsis, 삭제 크기 유지 | 밀도 유지. 뒷부분을 바로 확인하기 어려움. 원문·삭제 버튼 이름 유지, 포인터는 title로 확인. 키보드 시각 확인에는 한계가 있음 |

폭520px·글자13px·기존 바탕/경계는 유지한다. 짧은 파일명의 기본 행 높이는 유지하며, 적용 시 복수 파일·긴 영문·공백 없는 이름도 확인한다. 행정실 편집은1200px부터 검증한다.

## UP-Q2 파일 삭제 아이콘

기존 SVG 원은 #a3a3a3, X는white이며 호버 색이 별도로 없다. 기본 #737373, 호버 #404040으로 적용했다. 기존 중립색·보조 아이콘의 반응 패턴을 재사용하며 원형 X와19px 크기를 유지한다. 위험 행동색을 새로 정하는 제안이 아니다. SVG currentColor로 기존 neutral-500/700에 연결하고 호버·이탈·키보드 초점을 확인했다.

## 자료와 경계

[실측](file-review-comparison/measurements.json). 실제 공지 작성1280px에서 선택한 로컬 파일을 바탕으로 DOM 스타일만 바꿨다. 파일은 업로드/게시하지 않고 로컬 목록에서 삭제했다. 이전 제안 자료와 이번 실제 적용 캡처는 별도 폴더로 구분한다. 색 대비의 전체 접근성 적합성 선언은 하지 않는다.

파일·이미지 저장 로직, SunEditor 내부, Sonner는 변경 범위 밖이다. 닫힌 Dropdown 옵션으로 Tab이 이동하는 기존 문제는 Q-15, Image object URL 정리의 소스상 우려는 Q-16으로 계획에 기록했다.

## 실제 적용·검증

- 파일명은 min-width:0과 한 줄 ellipsis, 삭제는 shrink:0. 기존520px 폭·30px 높이·19px 아이콘·바탕/경계를 유지한다.
- 공지 작성1200/1280px에서 긴 한국어·공백 없는 영어·짧은 이름을 함께 선택했다. 모든 행520×30px, 삭제19px, 가로 넘침 없음.
- 기본/호버/이탈 색, DS-020 초점, Enter 삭제를 확인했다. 원문 title·삭제 이름도 확인했다. 브라우저 기본 툴팁 자체의 시각 표시와 키보드 표시를 검증 완료로 취급하지 않는다.
- 승인 B 견본의 파일명 영역(삭제 아이콘 제외)과 실제 적용은 픽셀이 동일하다. 삭제 기본·호버19px 견본도 승인안과 동일하다. [이미지 대조](file-controls-implementation/image-comparison.json).
- [실제 측정과 경계](file-controls-implementation/measurements.json). 로컬 파일 선택만 사용해 업로드/저장하지 않았다. 파일 처리 로직 변경 없음.
