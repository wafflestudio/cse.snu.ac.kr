# 중립색 역할 제안 — 배경·글자·경계

[현재 DS](index.html) · [역할 견본과 실제 화면 비교](neutral-roles.html) · [진행 현황](PLAN.md)

DS-009의 네 색 계열 가운데 **중립색을 사용하는 기준**을 구체화하는 C-Q4 제안이다.
아래 표는 아직 미확정이며 앱 색상은 이번 작업에서 변경하지 않았다. DS-007·008은 그대로 유지한다.

## 제안하는 기본 역할

| 역할 | 기본값 제안 | 사용 기준 |
| --- | --- | --- |
| 기본 면 | white #ffffff | 일반 페이지의 콘텐츠 영역, 기본 입력의 바탕 |
| 약하게 구분한 면 | neutral-50 #fafafa | 본문 패널·카드·목록의 교차 행 등 바탕과 약하게 구분할 영역 |
| 묶음을 드러내는 면 | neutral-100 #f5f5f5 | 표 머리글·안내 구역·보조 컨트롤 등의 묶음 |
| 일반 페이지의 어두운 큰 면 | neutral-900 #171717 | 제목·헤더를 감싸는 큰 면. 현재 PageLayout 사용 |
| 카테고리의 어두운 큰 면 | neutral-850 #1e1e1e | 현재 CategoryPage의 맥락별 예외로 유지 |
| 주요 글자 | neutral-950 #0a0a0a | 밝은 면의 본문·제목·정보의 핵심 내용 |
| 설명 글자 | neutral-700 #404040 | 프로필 설명·연락처 등 본문보다 한 단계 낮은 설명 |
| 읽어야 하는 보조 정보 | neutral-500 #737373 | 흰색·neutral-50 면의 번호·학점·날짜·부가 설명 |
| 회색 면 위 보조 정보 | neutral-600 #525252 | neutral-100·200 면에서 읽어야 하는 작은 보조 글자. DS-008의 secondary 글자도 이 조합 |

이미 결정한 입력 예시 neutral-500, 보조 버튼 글자 neutral-600, 입력 초점 neutral-700은 DS-008이다.
다른 컨트롤의 경계·초점·호버·활성·비활성 전체를 위 표로 일괄 결정하지 않는다.

## 왜 이 구분인가

현재 [PageLayout](../../apps/web/src/components/layout/PageLayout/index.tsx)은 어두운 상단과 흰 콘텐츠 영역을,
[CategoryPage](../../apps/web/src/components/feature/category/CategoryPage.tsx)는 neutral-850을 사용한다.
공지 본문과 카드·교차 행은 neutral-50, 표 머리글·안내 구역은 neutral-100을 사용하는 사례가 있다.
이 차이를 하나의 배경색으로 합치지 않고 선택 기준을 붙이는 제안이다.

본문의 neutral-950은 루트 기본값, neutral-700은 인물 소개·연락처·검색 요약 등에 존재한다.
보조 정보는 neutral-400과 500이 혼재한다. [CourseList](../../apps/web/src/routes/$locale/academics/-components/courses/CourseList.tsx)의
교과목 번호·학점·학년처럼 실제로 읽어야 하는 정보는 비활성 표현과 구분할 필요가 있다.

- #737373 / 흰색: 약 4.74:1, / #fafafa: 약 4.54:1.
- #737373 / #f5f5f5: 약 4.35:1. 회색 면까지 같은 글자색을 기계적으로 확장하지 않는다.
- #525252 / #f5f5f5: 약 7.17:1, / #e5e5e5: 약 6.20:1.

수치는 불투명 sRGB 조합의 계산이다. 전체 접근성 검증이나 비활성 컨트롤의 판정이 아니다.

## 남기는 예외

- neutral-75 #f8f8f8은 현재 교과 연혁 패널 등에 있다. 이번에 삭제하거나 50·100으로 통일하지 않는다.
- neutral-800 #262626은 활성 항목·강조 등에 쓰인다. 기존 사용처를 없애지 않으며 일반 본문의 모든 글자를 950으로 바꾸지 않는다.
- neutral-400은 비활성, 어두운 면의 보조 정보, 아이콘·장식 등 다른 맥락에도 사용된다. 전역 치환하지 않는다.
- 헤더·푸터·메인에 직접 지정된 어두운 값은 각 화면의 예외로 남긴다. 비슷하다는 이유로 통합하지 않는다.
- 입력 기본 경계, 검색창과 기타 컨트롤의 초점, 링크·오류·어두운 면의 상태별 규칙은 별도 비교가 남아 있다.
- 주황 #ff6914와 흰 글씨 조합은 DS-007에 따라 유지한다. Sonner·에디터 내부는 제외한다.

## 실제 화면 비교와 첫 적용 범위

로컬 실 API와 DS-008 적용 당시의 프로덕션 빌드에서 학부 교과목 목록을 열고, 동일 DOM의 콘텐츠 영역에서
실제로 neutral-400으로 표시되는 정보만 neutral-500으로 바꿔 캡처했다. 저장·API 데이터 변경은 없다.
한국어·영어 각각 1280·390px, 총 4장면의 전후 8개 전체 화면을 같은 크기로 전환해 볼 수 있다. 글자 크기·간격·배경·주황·줄바꿈 폭은 변경하지 않는다.

4장면 모두 콘텐츠 영역의 폭·높이·텍스트가 전후 동일했고 대상 정보의 색 변경을 확인했다.
로컬 데이터는 교과목 1개 표본이며, 모든 교과목·상태를 검증한 것은 아니다.
영어 390px 화면은 기존 푸터의 가로 넘침을 포함해 이미지 폭이 전후 모두 436px이다.
이는 Q-05의 배치 검토에 연결하며, 비교 문서의 원본 크기 보기는 이 실제 이미지 폭을 보존한다.

[원자료](neutral-roles-comparison/measurements.json). 이전 정식 러너의 이미지 빌드 시간 초과 이후
기존 로컬 API·프론트 빌드를 사용한 탐색 비교다. 앱 적용 확인이나 전체 회귀가 아니다.

승인 후 첫 적용은 다음 세 곳의 **밝은 바탕 보조 정보**다.

1. CourseList의 교과목 구분·번호·학점·학년.
2. CoursesPage의 RM/EM/LE 설명.
3. CourseToolbar의 선택하지 않은 보기 방식. 선택된 항목의 neutral-800은 유지.

배경·본문·경계의 표는 DS의 기본 사용 기준으로 문서화하며, 기존 전용 화면을 일괄 정규화하지 않는다.
다른 페이지의 도입은 실제 역할과 배경을 대조한 뒤 진행한다. 이번 질문은 **이 역할 구분과 보조 정보의 농도로 정할지**다.

## 비교 문서 확인

Playwright 1.57.0 Linux Chromium에서 비교 문서와 누적 DS를 1280·390px로 확인했다.
8개 이미지의 전환·로딩, 원본 크기 보기, 라디오의 화살표 키 이동, 문서 링크를 확인했다.
문서 자체의 페이지 가로 넘침은 없고 넓은 표·원본 이미지는 각 영역 안에서 스크롤한다.
이 문서 검증은 위에서 기록한 실제 앱 영어 푸터의 넘침과 구분한다.
