<Intro>

## 추상의 구상

컴퓨터공학은 0과 1에서 출발해 추상화의 층위를 쌓아갑니다. 하나의 구조가 다음 층위의 단위가 되고, 그 위에 더 복잡한 시스템이 세워집니다.

서울대학교 컴퓨터공학부의 디자인은 이 사고방식을 시각 언어로 옮깁니다. 간결한 형태가 정보를 담는 단위가 되고, 단위 사이의 관계가 화면의 질서를 만듭니다. 정보를 구성하는 방식에 학문의 정체성을 담습니다.

</Intro>

## 시각 언어

### 그래픽

메인 화면의 원과 막대에는 학부의 이름이 담겨 있습니다. 0과 1을 나타내는 여섯 행의 기호를 ASCII로 읽으면 SNUCSE가 됩니다. 컴퓨터가 문자를 표현하는 방식이 하나의 그래픽이 되며, 학문의 언어와 학부의 정체성이 만납니다.

<GraphicDemo />

### 연결선과 노드

원과 선으로 정보 사이의 관계를 표현합니다. 한쪽 또는 양쪽 끝에 노드를 두고, 직선과 45도 사선을 조합합니다.

<ConnectionsDemo />

연결선의 시작과 끝에서 무엇이 이어지는지 읽을 수 있어야 합니다. 관계를 드러내는 곳에는 노드를 사용하고, 정보 묶음을 단순히 나눌 때는 중립색 구분선을 사용합니다.

이동은 연결된 이름이 담당합니다. 선 자체에 클릭 동작을 부여하지 않습니다. 주황색 선은 밝은 본문에, 회색 선은 어두운 제목 영역에 배치합니다.

### 접힌 모서리

파일 아이콘에서 가져온 접힌 모서리는 함께 읽을 정보를 하나의 단위로 묶습니다. 오른쪽 위를 45도로 접고, 밝은 면과 그림자로 겹침을 표현합니다.

<FoldedPanelDemo />

선택한 항목은 주황색으로 드러내고, 읽기 위한 요약은 중립색으로 유지합니다. 접힌 모서리가 모든 영역의 클릭 가능성을 뜻하지는 않습니다.

접힌 부분 아래는 여백으로 남겨 글자가 겹치지 않게 합니다. 하나의 대상으로 읽는 정보에만 적용하고, 긴 본문이나 문서의 모든 섹션을 이 형태로 둘러싸지 않습니다.

## 색상

주황색은 서울대학교 공과대학 홈페이지에서 사용하는 색 계열을 이어받았습니다. 공과대학과의 시각적 연속성을 유지하면서 메인 그래픽, 주요 행동, 선택 상태를 드러내는 학부의 강조색으로 사용합니다.

## 타이포그래피

정보를 읽는 서체와 학부의 메시지를 전하는 서체를 구분합니다. 본문과 탐색에는 Pretendard Variable을, 메인 화면의 한글 슬로건에는 고운바탕을 사용합니다.

<Fonts />

<TypographyPreview />

제목은 짧고 단단하게, 긴 본문은 충분한 행간으로 구성합니다. 여러 줄이 되는 제목은 단어 단위로 줄을 바꾸고 크기만 줄여 한 줄에 넣지 않습니다.

## 레이아웃

탐색과 제목은 어두운 영역에, 본문은 밝은 영역에 놓아 위치를 파악하는 일과 내용을 읽는 일을 구분합니다. 소개 페이지는 여백으로 읽는 흐름을 만들고, 공지 목록과 예약 화면은 비교와 선택에 필요한 정보를 모아 배치합니다.

<LayoutPreview />

#### 정렬과 여백

정보가 적다고 본문을 가운데로 옮기거나 남은 공간을 채우지 않습니다. 제목과 본문의 시작선을 유지하고, 넓은 여백은 본문과 보조 탐색을 구분하는 데 사용합니다. 비교할 항목은 같은 위치에 배치합니다.

#### 작은 화면

주 메뉴는 접고 여러 열의 정보는 읽는 순서대로 쌓습니다. 입력란과 버튼은 문구가 잘리지 않게 배치하고, 표처럼 비교가 중요한 요소는 내부에서 가로 이동할 수 있게 합니다.

## 컴포넌트

같은 역할의 요소는 형태와 상태 표현을 공유합니다. 채움, 테두리, 글자색의 차이로 강조와 선택을 구분합니다.

### 버튼

채움과 테두리, 글자색으로 행동의 강조 수준을 구분합니다.

<ButtonDemo />

주황색 채움은 추가·재시도처럼 눈에 띄어야 하는 행동에, 짙은 회색은 저장·확인에 사용합니다. 함께 놓이는 보조 행동은 연한 테두리로 구분하고, 텍스트형은 배경 없이 문구만 남깁니다.

#### 배경에 따른 대비

텍스트형은 밝은 검색창과 어두운 메뉴에, 흰색 헤더형은 어두운 탐색 영역에 쓰입니다. 현재 텍스트형의 흰색 호버 상태는 밝은 배경에서 대비 보완이 필요합니다.

### 태그

둥근 윤곽과 주황색으로 짧은 분류 이름을 본문과 구분합니다.

<TagDemo />

윤곽형은 흰 바탕에 주황색 글자와 선을, 채움형은 주황색 바탕에 흰 글자를 사용합니다. 제거할 수 있는 조건에는 이름 오른쪽에 닫기 아이콘을 붙입니다.

### 체크박스와 라디오

사각 체크박스는 복수 선택을, 원형 라디오는 단일 선택을 나타냅니다.

<SelectionDemo />

체크박스는 중립색 체크 표시로, 라디오는 주황색 중심점으로 선택을 드러냅니다. 선택 표시와 이름을 가까이 두고, 선택할 수 없는 항목은 옅게 표시합니다.

### 드롭다운

현재 값과 아래쪽 화살표를 얇은 테두리 안에 함께 놓습니다.

<MenuDemo />

펼친 목록은 선택 영역과 같은 너비로 이어집니다. 선택한 값은 주황색 글자로, 초점이 놓인 행은 밝은 회색 바탕으로 구분합니다.

여러 선택지를 한눈에 비교해야 한다면 라디오를 사용합니다. 드롭다운은 현재 값에 집중하면서 공간을 아껴야 할 때 적합합니다.

### 날짜 선택

일정한 격자 안에서 오늘과 선택한 날짜를 서로 다른 표시로 드러냅니다.

<DateDemo />

오늘은 주황색 글자로, 선택한 날짜는 사각 테두리와 굵은 글자로 표시합니다. 연월은 굵게, 요일은 작게 두어 달력의 읽는 순서를 만듭니다.

### 페이지 이동

현재 페이지를 주황색 글자와 밑줄, 굵기로 표시합니다.

<PaginationDemo />

숫자는 일정한 간격으로 정렬하고 이동 화살표는 양 끝에 둡니다. 넓은 화면에서는 최대 10개, 모바일에서는 최대 5개의 번호를 보여줍니다. 이동할 수 없는 방향은 옅은 회색으로 구분합니다.

### 첨부 자료

얇은 테두리와 클립 모티프로 첨부 자료를 본문에서 구분합니다.

<AttachmentDemo />

파일명과 크기를 한 행에 나란히 놓고, 클립은 테두리에 걸쳐 배치합니다. 긴 파일명이 크기 표시를 밀어내지 않게 하며 여러 파일은 행을 나누어 정렬합니다.

### 다이얼로그

밝은 회색 바탕의 위아래에 주황색 선을 두어 집중할 영역을 구분합니다.

<DialogDemo />

제목, 설명, 행동 버튼을 세로로 정렬하고 닫기 아이콘은 오른쪽 위에 둡니다. 실제 화면에서는 주변을 반투명한 어둠으로 낮춰 다이얼로그와 배경의 층위를 구분합니다.

### 콘텐츠 입력

한 줄 입력과 여러 줄 입력에 같은 테두리와 레이블 규칙을 적용합니다.

<FieldDemo />

레이블은 입력란 위에 두고, 입력 예시는 옅은 글자로 구분합니다. 필수 표시는 레이블 옆에, 오류 설명은 입력란 가까이에 배치합니다.

#### 한글과 영문

현재 편집 중인 언어는 굵은 글자와 밑줄로 표시합니다. 두 언어에서 레이블과 입력란의 배치를 유지합니다.

### 파일 첨부

파일 선택 버튼 아래에 선택한 자료를 행으로 나열합니다.

<FileDemo />

목록은 밝은 회색 바탕에 놓고 점선으로 행을 구분합니다. 파일명은 왼쪽, 제거 아이콘은 오른쪽에 정렬해 이름의 길이가 달라도 같은 위치에서 찾을 수 있게 합니다.

## 접근성

색을 구분하기 어렵거나 키보드만 사용하는 경우에도 정보와 행동의 의미가 유지되어야 합니다. 새 화면을 구성할 때 다음 기준을 함께 확인합니다.

<ContrastPreview />

WCAG AA의 최소 대비는 일반 텍스트 4.5:1, 큰 텍스트 3:1입니다. 큰 텍스트는 24px 이상 또는 약 18.7px 이상의 굵은 글자를 뜻합니다.

<Callout>

밝은 주황 면 위의 흰 글자는 2.88 로 본문 기준에 미달합니다. 주황을 갈색에 가깝게 낮추지 않는 한 넘길 수 없어, **버튼과 태그의 짧은 라벨에 한해 브랜드 표현을 우선하기로 했습니다.** 읽는 글이 올라가는 면에는 진한 주황과 `neutral-950` 을 씁니다(5.44).

</Callout>

#### 선택과 오류

선택한 항목은 색과 함께 밑줄, 체크 표시, 굵기로 구분합니다. 오류는 해당 입력란 근처에 이유와 수정 방법을 적습니다.

#### 키보드 초점

초점 위치가 눈에 보여야 하고 화면의 읽는 순서와 이동 순서가 맞아야 합니다. 팝업을 닫으면 열었던 위치로 돌아갑니다.

#### 이름과 대체 설명

아이콘 버튼에는 행동을 설명하는 이름을 제공합니다. 의미 있는 이미지에는 대체 설명을, 장식 이미지에는 불필요한 설명을 붙이지 않습니다.

## 문구

제목은 내용을, 버튼은 행동을, 안내는 결과와 다음 단계를 설명합니다. 학부의 정보를 찾고 처리하는 데 필요한 내용을 짧고 구체적으로 씁니다.

#### 제목과 이름

“더 알아보기”보다 “연구 분야”처럼 대상을 적습니다. 같은 정보는 메뉴, 제목, 검색 조건에서 같은 이름으로 부릅니다.

#### 행동과 결과

“진행”보다 “예약하기”, “삭제하기”처럼 결과를 알 수 있는 동사를 씁니다. 되돌릴 수 없는 행동은 확인 전에 영향을 설명합니다.

#### 안내와 오류

“오류가 발생했습니다”로 끝내지 않고 “저장하지 못했습니다. 입력한 내용은 유지됩니다. 다시 시도해 주세요.”처럼 상태와 다음 행동을 알립니다.

#### 한글과 영문

두 언어에서 정보의 범위와 행동의 의미를 유지합니다. 영문을 장식적인 부제로 반복하지 않고 약어는 독자가 알고 있을 때만 사용합니다.
